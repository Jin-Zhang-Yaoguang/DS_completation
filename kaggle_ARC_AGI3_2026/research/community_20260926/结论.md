## 值得学的实现

1. **先学 [Just Explore](https://github.com/dolphin-in-a-coma/arc-agi-3-just-explore)，MIT，commit `c2d98318`。** `agents/heuristic_agent.py` 用同色连通块生成点击候选、按显著性与形状分组，并识别边缘 HUD；`graph_explorer.py` 记录状态转移、未试动作与到最近探索前沿的路径。我们的 `adaptive_agent.py` 目前只给稀有颜色、画面变化中心和固定点做候选，完整画面哈希可能把 HUD 变化误当成新状态。可先移植思想，保留自写实现及独立对照；旧版动作映射没有覆盖 `ACTION7`，且作者注明非确定性与大状态空间会使图搜索失效。
2. **再学 [Duck](https://github.com/Tufalabs/duck-harness) 的框架，GitHub commit `7652836056c5`。** `ARC3-Inference/inference/agent/tool_agent.py` 把分割结果、前后帧、转移历史交给临时 Python 工具，支持在一次调用中执行短动作序列，并按上下文预算淘汰旧消息；`README.md` 记录 Kaggle/vLLM 运行和回放工具。旧方案用 Qwen3.6-27B FP8、GPU 和大量依赖，不能直接当作我们的 CPU 基线。GitHub API 未识别仓库许可证，直接复制代码进提交前须核实许可；学习架构不受此限制。
3. **动画只做有条件的证据。** [TAAF Anim 复盘](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-3/discussion/734369)指出 25 个公开游戏中有 13 个会返回多帧，忽略中间帧可能丢失机制；但全量送给模型增加耗时，作者的相关调用大多没落在有信息的动画上。可先记录帧数、瞬时变化像素和边界框，在明确有用时再展开。
4. **Tycho / PRO-LONG 用于研究长期推理，不作首个复现目标。** Tycho 的可执行世界模型和验证器、PRO-LONG 的可检索长日志值得学；其报告使用付费前沿模型、不同评测口径。先抽取“假设—预测—验证”和关键发现持久化，不沿用其分数当 Kaggle 预期。

[Perception-Augmented Duck 讨论](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-3/discussion/743060)提供补充对照：作者自报隐藏分数 `1.43`，并称扩到 64k 上下文或把采样温度降至 0.3 的实验反而变差。这里没有独立核对对应 submission ID，故只把它当成待复核的实验线索。

## 冷启动顺序

1. 冻结 v4 源码、Notebook SHA 与 `56576143` 回执作为对照；不要覆盖有效提交。
2. 在相同 25 游戏、相同动作上限和相同种子集合下，分别测试 HUD 去噪、连通块点击候选、状态图回到探索前沿；逐项记录每局动作、关卡、耗时与失败。对有随机性的方案做重复运行。
3. 记录多帧事件与无变化动作，再决定是否引入动画特征和无效动作拦截；同时量化耗时，避免省动作却超 9 小时。
4. 只有对照结果与 Kaggle 实际 runner 都过关，才使用下一次每日正式提交。需要模型推理时优先评估 Kaggle 免费 GPU 与离线权重、wheelhouse 的可用性，再尝试 Duck 类框架。
