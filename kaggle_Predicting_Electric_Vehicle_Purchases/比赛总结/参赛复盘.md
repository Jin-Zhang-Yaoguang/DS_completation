## 比赛理解

任务是根据 13 个消费者特征，预测 `Will_Buy_EV=Yes` 的概率。训练集 668,665 行、测试集 286,571 行，无缺失，正类占约 17.46%。评估采用 ROC AUC，关注正负样本的排序。

### 收入是数值，也是离散结构

收入的精确值、粗细分箱、频次和上下文购买率带来很大增量。V2 相对原始 V1 的 OOF 增加约 0.003758；这比后续许多调参和融合变化都大。合成数据的这些关联不应解读为现实消费者的因果规律。

### 表示变化比同家族补丁更有价值

V101 的生成器感知线性模型 OOF 0.946420，已经超过此前 V100 的融合值 0.946398。它与 V100 的秩相关约 0.993，而旧强树之间接近 0.999。新模型提供了不同的排序视角，残差树再补上非线性。

生成器机制属于研究假设。GPT-2 token 特征有效，不等于已确认比赛实际采用 GPT-2 生成；报告应保留这个区别。

### 验证不是一个分数

嵌套 TE 只解决编码泄漏的一部分。外层验证折参与早停，仍会影响模型选择；全量 OOF 上拟合融合权重得到的是开发分数。截止日模型确实做了嵌套元层比较，但不应把整个流程称为完全独立的 outer 验证。

Public 与 Private 的样本、类别比例和排序对不同方法的敏感度不同。最终版 Public 比 Private 高 0.00109，不能仅凭这个差值认定过拟合；应看同一对候选在两块测试集的增量。

## 经验总结

### 做得好的

- 较早建立数据、ID、提交格式和 OOF 产物的对应关系，确保每次提交可追溯。
- 先验证精确收入编码，再扩展模型，而不是只做参数搜索。
- 保存失败和禁用产物；不把恢复运行或包装修复重新算成科学进展。
- 截止日从社区机制出发，复现线性起点、donor 基底和残差模型，得到可检验的变化。
- 以逐折增量和边际贡献决定融合成员。V103 与已有残差树秩相关 0.9996，几乎无融合增量；最强单模也不自动成为最好成员。

### 做得不好的

- 很早的计划已经写了 Logistic Regression sanity check，却到截止日才真正把强线性模型放进主线。
- 不同工作目录的实验记录分散，V101 之后的源码和台账未及时归档到主线；本次补充了最后阶段台账与精简结果，不声称补齐了全部源码。
- 部分最终候选低于原先晋级门槛后仍因授权提交。授权例外应单独记录，不能反过来更改历史门槛。
- 严格协议和元数据检查曾占用大量时间。探索阶段应允许明确标注的廉价筛查，最终候选再完成全量确认；筛查不能直接晋级。
- macOS 上 torch 与 LightGBM 的 OpenMP 冲突需要进程隔离。训练停滞应先核对进程、日志与 checkpoint，再判断方法失败。

## 心得迁移

### 写作模式

每个实验只回答一个问题，写清“假设、唯一改动、同口径对照、逐折增量、结论”。过程日志留在实验台账；复盘正文只讲能改变下一次决策的证据。

### 内容管理

使用一个版本注册表，记录代码哈希、数据与切分哈希、OOF / test 对应关系、父成员、研究状态与线上提交 ID。知识、当前执行状态和候选结果分别维护，避免旧结论被复制成当前状态。

### Agent 设计

研究、执行和审计的职责要清楚。研究负责提出可证伪机制，执行负责产物完整和恢复，审计负责泄漏、选择偏差与身份对应。每项长任务只有一个运行实例；队列和日志应能够证明它确实在运行。

先以便宜筛查找方向，再用冻结全折和嵌套选择确认。预算包括 CPU / GPU、时间、提交次数；到预算或停止条件就关闭该分支。AI 给出的“这条路不通”只有在具体实验边界内有效，不能代替新的反例检验。

### 文件形式

Markdown 是可编辑、可比较的正文，HTML 是阅读页面。图表绑定同一份 JSON；二者一起归档，避免页面漂亮但数字无法核查。HTML 单文件离线可读，左侧导航保留四个模块。
