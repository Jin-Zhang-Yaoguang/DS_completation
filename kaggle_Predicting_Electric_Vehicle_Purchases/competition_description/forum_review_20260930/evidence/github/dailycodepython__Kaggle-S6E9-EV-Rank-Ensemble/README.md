## 🚀 Notebook Architecture & Options

Standard probability averaging often fails in Kaggle tournaments due to uncalibrated models skewing the final distribution. This notebook bypasses this limitation by converting raw probability predictions into **Normalized Percentile Ranks**, providing two distinct execution tracks:

1.  **Track A: Dual-Headed Percentile Blend (Active Top-24 Baseline)**
    *   Blends two top-tier public submissions using a fine-tuned weighting ratio (46% / 54%).
    *   Achieves the peak public leaderboard score of **0.94656**.
2.  **Track B: Three-Headed Triad Ensemble (Robust Insurance)**
    *   Integrates an additional orthogonal model architecture to diversify predictions.
    *   Uses **Nelder-Mead optimization (`scipy.optimize`)** to dynamically calculate the most stable weight configuration, balancing the models out roughly evenly (~0.33 each) to prevent Private Leaderboard shake-ups.

---

## 🧠 Key Methods Implemented

*   **Rank-Based Normalization:** Transforms raw probability outputs via `.rank(pct=True)` to standardize inputs onto a single unified scale before ensembling.
*   **Nelder-Mead Optimization:** Multi-model weight optimization that dynamically converges on stable parameters based on cross-model variance.
*   **Quantile Projection:** Re-maps the final blended ranks back into target probability space using `np.quantile` to perfectly preserve the expected macro-distribution of the competition dataset.

# ⚡ Kaggle Playground Series S6E9: Решение Топ-1% (24-е место)

Репозиторий содержит оптимизированный ноутбук для соревнования **Kaggle Playground Series (Сезон 6, Эпизод 9)**: *Predicting Electric Vehicle Purchases* (Прогнозирование покупки электромобилей). 

Разработанный конвейер (pipeline) использует **ранговый блендинг (Rank-Based Blending)** и математическую оптимизацию весов. Этот подход позволил занять **24-е место (~Топ-1%) среди более чем 2400 участников** с результатом **0.94656** на публичном лидерборде.

---

## 🚀 Архитектура и возможности ноутбука

Обычное линейное усреднение вероятностей на Kaggle часто не работает из-за разной калибровки моделей, что приводит к перекосу финального распределения ответов. Этот ноутбук решает проблему алгоритмически: он переводит сырые вероятности в **нормализованные перцентильные ранги**. 

В ноутбуке реализовано два сценария работы:

1.  **Сценарий А: Двухголовый ранговый бленд (Текущий Топ-24)**
    *   Объединяет два лучших публичных решения с тонко настроенным балансом весов (46% / 54%).
    *   Обеспечивает пиковый скор **0.94656** на Public Leaderboard.
2.  **Сценарий Б: Трёхголовый ансамбль (Страховка для Private LB)**
    *   Подключает третью, независимую архитектуру модели для диверсификации предсказаний.
    *   Использует **оптимизатор Нелдера-Мида (`scipy.optimize`)** для автоматического подбора весов. Алгоритм сбалансировал влияние моделей примерно поровну (~по 0.33), что минимизирует риски падения (shake-up) в финальный день турнира.

---

## 🧠 Ключевые методы и фичи

*   **Ранговая нормализация:** Трансформация ответов через метод `.rank(pct=True)` приводит предсказания всех моделей к единой шкале (от 0 до 1).
*   **Оптимизация Нелдера-Мида:** Алгоритм автоматически рассчитывает идеальные веса для ансамбля, исключая человеческую предвзятость при ручном подборе по сетке.
*   **Защита от генеративного шума:** Логика блендинга спроектирована так, чтобы изолировать и сглаживать логические аномалии, характерные для синтетических данных турнира (CTGAN).
*   **Проекция квантилей:** Финальные сбалансированные ранги возвращаются в физический масштаб вероятностей через `np.quantile`, идеально повторяя макро-распределение целевой переменной.

## 🛠️ Как запустить в Google Colab

Ноутбук полностью автономен и подготовлен для выполнения в облаке Google Colab:

```python
# Пример логики рангового блендинга в коде
rank1 = top1['Will_Buy_EV'].rank(pct=True)
rank2 = top2['Will_Buy_EV'].rank(pct=True)

blended_ranks = (rank1 * 0.46) + (rank2 * 0.54)
final_sub['Will_Buy_EV'] = np.quantile(top2['Will_Buy_EV'], blended_ranks).round(5)
```
