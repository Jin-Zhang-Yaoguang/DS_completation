# C/D 对照比较入口

科学合同是本目录 `PREREGISTRATION_R01.md`；原 `PREREGISTRATION.md` 保留 C 算法及预算部分，候选选择以 R01 为准。本文件只说明实现。比较代码单独冻结，C CPU 和既有 A/B 运行记录均只读。当前仅准备与合成测试，没有真实装配、评分、训练或提交。

- D 是唯一候选，C 是旧算法对照。既有 B−A 必须整体严格为正、五折全部为正且独立复算、来源、最终监督均通过，才允许启动 C。最终重建资格还要求 D−C 整体严格为正、五折全部为正。A−C/B−C 仅解释，D 失败时不能改选 A/B。研究晋级单列 D−C 至少 +0.0001/五折，不要求 B−A 也达到 +0.0001。
- 所有 A/B 缓存、原最终 pipeline 成功、原评分及独立验证的 SHA 链、GPU version1 的归档证据，以及全部 C 10 份缓存/400 个原子/最终预算成功，必须先齐备。缺文件时只报 NOT_READY，不加载预测或标签。
- A/B 的旧 `verify_all()` 会重写其独立报告，因此本入口不调用它。复用其中只读的来源/缓存检查和纯 `independent_meta()`，按已经冻结的报告和输出独立重建 A/B，不改变旧目录。
- C 原子和家族缓存由冻结的 `legacy_cpu.check_family_cache()` 逐原子核验，明确 H 标签可用于早停、U 不可见。CT 共享相同 T/U 的合法 OOF/fullfit/foldmean 缓存。C 调用 `fit_v100_meta()` 时只传 T 标签，用自己的 CPU OOF 重新拟合 ECDF/权重，同一次拟合产出 C 和 D；不搬 A/B 元权重。独立验证用冻结 `independent_meta()` 分别复建 C/D，两臂都须逐元素误差不超过 1e-12。
- 每阶段先完整核验所有缓存，再处理元层。五个外层全部装配并独立重建通过，才读取完整目标，一次性计算 D−C 主要比较、A−C/B−C 解释项、既有 B−A 一致性。共享影响函数工具和 sklearn 分别复算整体/每折 AUC。条件区间不代表新盲测或训练选择的不确定性。
- `freeze` 要求根任务独立 `COMPARISON_REVIEW.json` 为 PASS，并精确绑定当前 compare/test/notes/R01 四项 SHA 和测试记录 SHA；测试必须至少 23 项、失败/错误/跳过均为零，原始日志及守护进程源码也须一致。配置固定这些审查与代码、R01、选择修订记录、C 配置和 A/B 配置等 SHA；完整缓存快照在运行时固定。
- 真实模式各由一次性监督器限制 1800 秒、16 GiB 全进程树（含监督器）、2 线程，保留四个生命周期检查、日志及失败结果。工作进程还复用冻结 `legacy_cpu.spawn_parent_guard()`：独立守护进程每 0.25 秒检查监督器 PID/创建时间，父进程消失或身份检查异常即终止整个工作进程组；原生排序/元拟合持有 GIL 时也能执行。握手成功后才运行元层/评分，握手证据绑定进最终 stage 结果。已有 STARTED 或结果不得自动覆盖重跑，包括父进程异常终止留下的未闭合阶段。
- `score` 会重新执行只读独立复算，防止复用陈旧 PASS。分数先写 `results.pending.json`，由监督器通过发布前边界后原子生成 `results.json`。如果发布后最后检查失败，即使结果文件已存在也不具资格。下游必须调用 `require_successful_comparison()`，同时验证 assemble/verify/score 成功终态、同 PID、预算检查、日志和最终结果 SHA；单看分数文件或其中资格字段无效。
- 实际 test 预测和比赛提交始终为 false。通过后只得到另立 D 全局 test 重建合同的资格：可复用审计后的旧 V90，CT 必须同批新 OOF/test 并重新拟合最终元层，详见 R01。本比较入口不实施部署。

待根任务独立审查及 C 配置稳定后，准备顺序为 `freeze` → `status`。全部门禁齐全才执行 `assemble` → `verify` → `score`，最后由 `require_successful_comparison()` 审核资格。当前不要执行真实模式。
