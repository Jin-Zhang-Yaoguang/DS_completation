# dd：Replay 蒸馏家族

目标：获得三个在冻结 y68 全家族及独立新种子上稳定胜出的模型。
版本按 dda、ddb、…、ddz、ddaa 顺序递进。每版记录假设、数据、训练产物、代码哈希、对照和失败原因。

## 技术边界

- 从公开高分 replay 的可见观测学习动作、任务、资源安排；可使用非参数原型、决策树、神经网络、分层计划及模拟器纠错。
- 原型检索明确称为非参数行为克隆，不冒充神经网络压缩。教师没有提供 logits/Q 值；没有可调用教师时不得宣称 DAgger 专家标注。
- 不调用 y68 或既有完整策略生成候选动作。y68 只用于动态对战评估。可以复用无策略编码器和官方规则原语，须记录来源。
- 输入不包含 episode ID、seed、教师身份、未来商店或对手私有状态。seed 仅用于切分和比赛驱动。
- 训练、开发、门控、独立确认分开。已经看过的 replay 留出只表示未参与训练，不是研究过程盲测。
- 本任务只授权本地研发和评估，不自动提交 Kaggle。

## 稳定胜出标准（先登记后评估）

对 manifest 中所有当前发现且按源码 SHA 去重的 y68 版本，用官方 1.32.7 动态对战。
每个候选代码和数据冻结后，依次跑两个互不重叠的 16 seed × 双席位面板。
每个面板、每个对手均须满足：

1. 至少 30/32 严格胜出（平局不算胜）；每个席位至少 14/16 胜。
2. 按 seed 对双席位胜差取平均，均值的 95% bootstrap 下界 > 0。
3. 无异常、提前结束、非法输出或计时预算超限；全部结果完整，缺失不算通过。

每个候选使用独占种子；失败面板转为诊断，不再称为新确认。开发采用多个对手的低成本小面板，明显落后就停该版。
三个模型必须分别通过，且有可解释的学习/规划/纠错差异；同一权重换名字或仅更改随机种子不计三个。
本地计时不等于 Kaggle 服务端计时，最终另做部署包隔离验证。

## 随机流边界

官方 `_end_of_day` 在绘制新商店前，按双方空地逐格抽杂草随机数。策略改变空地数量会改变后续商店所用的随机数。因此同 seed 不保证不同策略看到相同商店；开发差值包含这条环境反馈，正式验证需要充分独立 seed。后续逐日和终局结果记录可见商店序列，不强行改写官方规则。

## 采购标签语义

`audit_executed_purchase_labels.json` 与 `executed_purchase_labels/manifest.json` 保存请求/真实成交对照。M&M 的 146 条回放请求 25882 只动物，实际成交 3343 只，零成交回合占原请求数量权重的 87.08%。用于蒸馏生产配置时不能直接按请求数量加权；原始请求仍可作为条件重试策略的研究数据，不将其等同于无用动作。

`ddar` 使用请求比例，`ddas` 使用成交比例，均为离线监督回归树，输入只含决策前可见状态和已编译的计划采购总量。两个版本是同一模型路线的标签对照，不能计作两个独立成功模型。
