# V54 谱系第一性原理:对手指纹 + 策略带查表(四轴架构)

> 2026-09-22 定稿。V54 谱系(v54 / v54r1 / 后续 r 系)的一切扩展都在此框架内进行,不再另起炉灶。
> 首个实例:v54r1(提交 56447333)。

## 本质

V54 谱系 = 静态带库 + 一张「(对手族指纹 × 环境条件) → 带子」查表。
所有上分改动归结为:**给这张表加行、加列、加值,或自动化表的生成**。
不触发即回落原生 V54,误判成本为零——这是整个架构的安全底座。

## 四轴

### 轴1:对手池扩容(表的行)
- 指纹 = t2 观测 `(对手现金, 市场小麦库存)`(rkey),对确定性脚本是唯一指纹。
- 已建 7 族指纹库(rkey_lib.json):V52/53、V54镜像、V41/43、V38系、qq、y68买13系、y68r2。
- 扩容优先级由**线上人口分布**决定:从 replay 统计各族出场频率,高频族先补格子。
- V54 上榜后开源 fork 人口将持续上升 → 已覆盖格子的触发率自动升值。
- 对非确定性/轻改 fork:t2 单点指纹 → 多时点投票(t2+t26+t50)/最近邻匹配,松弛识别。

### 轴2:策略带扩容(表的值)
- 现状是「选带」:克制带只能从 V54 自带 41 条里选,上限受限于带库。
- 升级为「造带」:固定对手为某族脚本,用搜索/调度器在该对局环境滚新带,存为第 42+ 条。
  (即复刻作者 tools/claude_build_*.py 生产线;kagsim 零差异引擎已具备条件。)
- 最肥靶子 = 镜像局:对手带子完全已知,存在理论"完美抢跑带"(每个商店需求先它一步)。
  v54r1 的 5/6 只是换带打破对称,离针对性抢跑还有大空间。

### 轴3:决策时点扩容(表的列)
- 现状只在 t144(首店解锁,唯一已证无损切换点)决策一次。
- 商店每 72 步解锁一家(t144/216/288/360/432/504/576),每个解锁点都是新信息到达点。
- t300 二次路由曾在 y68 底盘上证伪(无条件切换);但在「仅同族、仅确定性对手」窄条件下,
  中盘二次切换可本地精确复算,值得按窄口径重测。切换风险=带子耦合断裂,须逐局验证。

### 轴4:表生成自动化(维护流水线)
- 与作者拉开差距的关键是**生产线**而非某一版模型。
- 日更闭环:拉新 replay → 更新指纹库(检测新族/漂移)→ 对新/高频族跑同族搜索
  → 留出选表 → 独立复验(胜负优先筛选)→ 过 gate9 → 条目进表 → 打包。
- 表是纯数据,底盘不动:每次更新风险低、验证成本固定。

## 铁律(继承,不因本架构豁免)

1. 进表门槛:独立 seed 复验 + **胜负优先筛选**(净增大但胜局降=假金)+ gate9 零退步。
2. 单 seed 结论无效,须多 seed;每格子 ≥30 局独立复验。
3. 市场单顺序铁律、部署口径铁律(入口=exec 最后一个 callable)照旧。
4. 带子=高度耦合最优化产物,带内局部改动默认下坡;改动只发生在「整带切换」粒度。
5. 对真启发式对手(SpaTaro 类)本架构失效,交由风格池 v2 轨迹签名,不混入本表。

## 修正(2026-09-22 晚):换底盘必须「重选格值」,而非只复验格有效性

此前换底盘流程(V54→V56→rescue7)只做了一件事:确认已进表的格「仍优于新底盘基线」。
这漏掉了关键一步——**在新底盘上重选该格的最优带**。

实测后果(格值精炼实验,16 格 × 13 候选 × 5 seed × 3 子族,3081 局):
- 16 格中 **12 格的现值不是最优**;
- 其中 2 格现值已是**负收益**:ICE|BRUNCH 现 110 = 3/15(-1612),最优 107 = 15/15(+478);
  FM|ICE 现 110 = 3/12(-187),最优 120 = 12/12(+373);
- 另有多格从 8~13/15 提升到 15/15。

原因:格值是「带 × 我方底盘运营层 × 对手」三方耦合的产物。底盘运营层一变(V56 的止漏层、
rescue7 的终局模拟+订单簿),最优带就漂移。只验「优于基线」会让一个次优甚至负收益的带留在表里。

**新流程(换底盘标准动作,补第 4 步)**:
1. 重做底盘适配器(fr 探针 / 插入点 / 入口口径);
2. 表迁移 + 逐格复验「是否仍优于基线」;
3. **逐格重选最优带(候选短名单 × 索引 seeds × 多子族,配对口径)**;← 新增,不可省
4. 改值格用留出 seed 复验;
5. 三件套(gate9 / 动作带 / 家族 h2h)。

配套基建:combo_index(seed→组合索引)使第 3、4 步成本可控——精炼一格约 200 局,
全表 16 格约 3000 局,一次过夜即可。

## 重大风险(2026-09-24):任何 fork 改开局都会让我们的表失效

Dmitrii 于 09-23 发布 "Herd-Safe Sale Window",内容 = rescue7 + **21 行开局流动性层**:
```python
V9_OPENING_STEP0 = (("BUY_PRODUCT","WHEAT",8), ("SELL","WHEAT",3))
```
底盘、带库、所有其他层完全相同,但因为它动了 step 0 的小麦买卖量,
**rkey 从 (1042.0, 9989) 变成 (1046.0, 9989)** —— 我们 40 格表对它一格都不触发。

后果:r14 对 herdsafe 只有 9/16(56.2%),而对 rescue7 是 13/16(81.2%)。
haideptry 的 fork "Shepherd's Ledger" 同为 1046 键,已有 3+ 个 fork 在扩散。

修复:把 1046 加入镜像行与 t216 层的触发键(一行),对 herdsafe/shepherd
立刻回到 13/16(81.2%),均分差 +37 → +205,对 rescue7 无退步。

### 这是结构性风险,不是一次性事故

rkey 指纹的本质是"对手开局的市场足迹",而开局层是作者最爱改的地方(成本低、收益直接)。
**每次有人改开局,我们的整张表就对那一族失效。**

### 防御机制(须纳入轴4 日更)

1. **每日扫描新 rkey**:从新 replay 与新发布的 notebook 中提取 rkey,与白名单比对;
2. **新键自动适用性测试**:对新键跑 16 局对撞,比较"表触发 vs 不触发"。若表直接适用
   (如 1046),把新键加入白名单即可(一行);若不适用,才需要单独选值;
3. **不要用容错匹配**(如 1042±10 都算镜像键):实测邻近键属于完全不同的族 ——
   1041 与 1042 只差 1 但族不同,1039=V41/43、1035=V38、1036=qq、1044/1055/1059 未知。
   必须维护显式白名单。
4. 白名单当前状态:镜像行键 = {(1042.0,9989) rescue7 系, (1046.0,9989) herd-safe 系};
   K52 行键 = {(154.0,9959)}。K52 族若出现改开局 fork 会有同样问题,需同样监控。

## 战术原理(2026-09-24):表外格 = 镜像局,胜负由现金边际决定

分阶段诊断(r17 vs rescue7/herdsafe 的无解格与弱格,记录各商店解锁点的现金差):
- 表外格中,我们与对手用同一底盘、不查表时选同一条带 → **现金差到 t288 精确为 0**;
- 胜负由极薄的层差异决定(RACE 窗口、开局滑点),因此"全 41 带无解"并不代表带库缺好带,
  而是**问题根本不在选带**;
- herdsafe 对我们 4/4 全胜的机制:它的开局(买8卖3)比我们(买20卖15)少付约 8 金币滑点,
  这个差额从 t72 保持到终局,在镜像局里就是决定性的。

推论与做法:
1. **任何能在镜像局里拿到现金边际的改动,都直接转化为表外格胜率**。这是比选带更大的杠杆 ——
   表外格占镜像键组合的一半以上。
2. 带的"战术优化"首选在不破坏段内耦合的位置下刀:开局段(纯市场单,不影响地块/RNG)、
   层参数(RACE 窗口等)、切点拼接(段与段之间)。
3. **改我方开局会使我们观测到的全部 rkey 平移**(我们的成交量影响对手成交价)。
   每次改开局必须重测全部已知族的 rkey 并重映射表键,并检查撞键(r18 下 y68i 撞上 herdsafe 键 1042)。
   t150/t160 门格签名同样会漂移,需要重测。

实例:r18b = r17 + herdsafe 开局 + 表键重映射(1042→1038、1046→1042、154→152)。
bench 660 → 672(+12):herdsafe 74.2%→81.2%、rescue7 83.6%→85.2%,其余零变化;gate9 288/288。

## 轴2 扩展:带的三种战术优化方式(2026-09-24 实证)

值空间不只是 41 条完整带,而是"带的改造与组合"。三种方式都不碰段内耦合:

1. **改开局段**(纯市场单,不影响地块/RNG):镜像局胜负由现金边际决定,开局 7/2 是唯一对两大族现金差皆为正的开局。
   代价:改我方开局会使全部 rkey 平移,须重测重映射并检查撞键。
2. **晚切点拼接**(t144 原带 + t288/t360/t432/t504 后换带):
   - 镜像键 25 格、K52 键 18 格、metav4 键 17 格在留出中通过,零跨族伤害;
   - **羊毛店(YARN_STORE)世界是带库的共性缺陷**:三个键上均为 t288 起切到 0/100/101/112/120 后每局多赚 2000~5800,
     与对手是哪一族无关。
3. **t144 整带换**(即传统"选带"):在已精炼的键上仍有少量空间,但在新键上**粗筛收益大多是噪声且可能崩盘**
   (metav4 键粗筛约 25 格,留出仅 2 格通过;PET|ICE 5/5→0/5、FM|SMOOTHIE 5/5→0/5,并常伤同键老族)。

**规则**:搜索时优先晚切点;t144 整带换需要 ≥8 局留出且必须过同键全族安全;
粗筛单局/双局结果只作候选,入表必须过留出。验收优先用未参与任何选值/留出的独立索引(combo_index3)。

## 轴5:执行层(2026-09-26 立轴)
- **定义**:轴1-3 决定"生产什么"(行=指纹/谱系,值=带,列=切点);轴5 决定"怎么成交" —— 每回合 market 列表的生成后处理(挂单顺序、卖出时机、合并/补位、资金顺序)。
- **取值 = 执行层组件库**,每个组件带开关(`_exec_on(layer, obs)`);开关表 `_exec_mask` 可按 键×谱系×组合×时段 查表,本地消融用 `KAG_EXEC_OFF` 探针。
- **与轴1-3 近似正交**:换执行层后 cha 表仍有效(138→169/288),老 bench 同步上涨。
- **选法**:逐层消融(新对手 bench + 真实动作带 + 老 bench 三集合计)→ 贪心第二轮 → 独立种子确认。
- **v1 结果**:MPX −52、MP −32、FX −23 为主力;DAWNPX 有害(关闭 +43,确认 +40),BUYDIP 小害(+6/+7),二者全局关闭;MA/WB3/MG/R25 ≈0。
- **纪律**:组件间有依赖(FX 依赖 MA 分类器),嫁接后检查函数重名与各层 errors 遥测。

## 2026-09-28 优化框架(用户采纳):方向 0-3 + 价值排序
- **方向 0 通用实力**:执行层/生产层,不依赖识别,对所有人群生效(例:r34 嫁接新版尾部执行层,动作带 +97/1292,各人群均涨)。
- **方向 1 识别覆盖**:只对"能反制"的人群追求覆盖(Majkel 式自适应好识别但无代表,暂缓)。
- **方向 2 准确与保真**:拆成 分类准确(键/谱系归对)+ 代表保真(真实棋盘胜负一致率);每日在近期棋盘复核,保真下降即重建(09-27 人群换代曾让旧表一夜失效)。
- **方向 3 针对应对**:有高保真代表(≥90%)→ 最优应对(全 41 带 × 多切点穷尽);混合体/无代表 → 稳健应对(多代表交叉)或不针对,交给方向 0。
- **价值排序**:人群价值 ≈ 目标分段占比 × 胜率缺口 × 是否有高保真代表。
- **统一验证**:真实棋盘分半(A 选 B 验)+ 两个代表交叉;不再跑 gate9。
