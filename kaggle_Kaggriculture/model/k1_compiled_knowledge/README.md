# K1 知识编译型四层 agent（k1_compiled_knowledge，2026-09-13 立项）

## 设计一句话

**框架永远不变，变的只是数据**：策略骨架（代码）稳定，所有随生态变化的东西
（日程表、商店表、对手指纹、反制参数）全部是数据资产（`knowledge.json`），
由自动管线从 replay 刷新。新对手出现时改数据，不改代码，不换范式。

架构蓝本 = Majkel1337 逆向（`v71_majkel_reverse`，LB#1 3237）：
t0 一次性重计算 + 零方差固定日程 + 反应式任务调度 + 市场节拍卖出。
执行器骨架源自本仓库原创的 v4_demand_race。

## 五层结构

| 层 | 职责 | 实现 |
|---|---|---|
| S0 知识包 | 日程/卖出规则/现金参数/调优旋钮，零魔数 | `knowledge.json`（打包时内嵌） |
| S1 t0 初始化 | 载入知识包，按商店分支选表 | `_get_state` / `Schedule` |
| S2 战略日程 | 人手/买地/建栏/动物/作物面积/施肥预算查表 | `Schedule.*` |
| S3 反应式调度 | 任务生成→优先级桶+最近邻+先纵后横寻路 | `build_tasks` / `assign` |
| S4 市场层 | 节拍卖出(t%4)+卖肥阈值+采购日程+现金守卫 | `market_orders` |
| S5 守护层 | 烂窗抢收/濒死喂养/终局清仓 | 分散在 P0/P1/终局分支 |

## 自动化管线（外圈）

- `profile_opponent.py <Team>`：任意队伍 → 对手卡片（录带判别、雇工/买地/卖出相位
  行为参数、可收编性建议、`--export-tape` 导出最强局带）。已用 Majkel1337 验证，
  自动取证与 v71 人工逆向一致。
- `tune_cem.py`：solo 口径 CEM 旋钮搜索（已证伪，见教训 3）。
- `tune_vs.py`：**对战口径** CEM（fitness = 对分层对手池的 margin）。
- `build_submission.py`：knowledge 内嵌 → 单文件 → tar.gz；`_ENTRY` 口径 + 48 步 parity 自检。
- `selfcheck.py`：B1 达标线自检（solo bank、空闲率、浇水/喂养覆盖、日程曲线偏差、现金曲线）。
- `debug_probe.py`：深度探针（动作分布、逐品卖出收入、买地/施肥时刻）。

## 教训（负知识，勿再踩）

1. **优先级桶饥饿**：种植/施肥排低桶时永远轮不到（浇水/喂养每回合吃光单位）。
   解法不是抬优先级（会反噬覆盖率），是 P3+ 大桶按(距离,优先级)排序让同块任务串联。
2. **面积必须跟着执行能力走**：铺面积超出「每天浇一遍」的能力=作物枯萎+白花种子钱。
   日程表天生是日增量式的（Majkel 草莓每天+4~6 块），另加日种植限速兜底。
3. **solo fitness 已证伪**：对 PASS 优化会把组合推向高价品集中（草莓/奶），
   在共享市场竞争下被对手供给砸穿价格。fitness 必须用对手池 margin
   （Majkel 每局卖 428 个小麦=低弹性品抗压，正是对战口径的解）。
3b. **对战口径旋钮搜索也已到顶**（tune_vs 8 代：训练 margin −85k→−64k，
   holdout −99k 不优于基线 −93k）：与 y67 带（150k 级）的差距是**结构性执行密度墙**，
   不是参数问题——同构于 v55「20 轮迭代封顶 55-60k」与启发式线「Majkel 旋钮
   嫁接 V38 全负」。出路在 S3 算法级改动（分区驻守、任务束、一次出门带齐补给），
   不在继续转旋钮。
4. 引擎日初清工：hands 快照要在 h2 拍，h0/h1 是重雇窗口。
5. 动物 14 点后不放置（当天喂不上，连续两天未喂即逃走）。
