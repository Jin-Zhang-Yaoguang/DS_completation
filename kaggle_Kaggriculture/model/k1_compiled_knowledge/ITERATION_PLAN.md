# K1 启发式迭代轮次设计（ITERATION_PLAN.md，2026-09-13）

依据：大一统框架纪律（OPERATIONS.md 总则）+ Majkel 决策粒度取证 + 两轮搜索的
E5 信号（参数/日程空间均调不动对战 margin）+ 对战收入归因铁证。

## 一、决策粒度金字塔（Majkel 机制映射到框架）

Majkel 的「低重复」来自分层节奏：宏观零方差、微观高频反应（跨局第 5 步即分叉、
卖出按 t%4 节拍、任务逐步就近）。K1 框架天生同构，四层各有迭代载体：

| 层 | 节奏 | 决策内容 | 框架载体 | 迭代手段 |
|---|---|---|---|---|
| L0 赛季级 | t0 一次 | 日程表族选择 | knowledge.json 表 | A2 离线搜索 |
| L1 日级 | 每 24 步 | 面积/雇工/买地/动物/角色重排 | Schedule 查表 + plan_roles | 表修订 + 旋钮 |
| L2 节拍级 | **每 4-5 步** | 市场卖出/对手供给响应（Majkel「每五步调整」对应此层） | market_orders 的相位/race 段 | 层实验（场景 4） |
| L3 步级 | 每步 | 任务分派/寻路/守护 | build_tasks + assign | 算法改动（场景 7） |

迭代原则：**每轮只动一层**，层间通过 knowledge.json 与 st 状态解耦，
一轮的失败不污染其它层的知识。

## 二、轮次结构（每轮 0.5-1 天，与提交额度/门控节奏对齐）

```
假设（来源：归因/卡片/搜索收敛，必须有数据出处）
  → 框架内实现（旋钮 / 层挂点 / 表修订，参数一律进 knowledge）
  → 验证链（selfcheck → 16 seed 配对 racing → holdout）
  → 判定：正（t≥2 且 holdout 正）→ knowledge 入库 + git 提交
         负 → README 教训区（负知识与正知识同价）
  → 下一轮假设从本轮证据里长出来
```

夜间穿插：E1/E2（patrol+卡片）刷新数据；A1/A2 后台搜索消化白天入库的新知识。

## 三、轮次队列（按当前证据排序，每轮标注假设出处）

### R1（下一轮，靶点已锁定）：S4 市场对抗——收入保卫战
- **证据**：对战归因铁证（2026-09-13）——solo→对战卖出量不变（奶 137→136、
  工作动作 1467→1463），收入 114k→38k 蒸发 67%（136 个奶只卖 3,178）。
  K1 对战掉分 100% 是被对手同质供给压价，不是执行。
- R1a 卖出错位（L2）：打开 race 层（已实现，默认关），扩展为「供给窗口检测」——
  对手近 K 步在抛某品 → 本品暂缓小批卖出改囤（等价格回弹）或立即整仓
  （抢在更低前），两个方向 racing 对决；
- R1b 品类错位（L1，**带底盘做不到、K1 反应式天生支持的事**）：每日角色重算时
  读市场价格与对手供给流，新增面积从被压价品转向空档品（价格低于 base×θ 的
  品类停止扩种，转向价格仍高的品）——「转产」在带底盘 9 次证伪，但 K1 的
  角色是每天重算的，转产成本=一次查表；
- 出口指标：vs y67 的 own bank 从 18k 抬升（不看 margin 先看收入保卫）。

### R2：低弹性锚（L0/L1）
- 证据：Majkel 卡片（每局卖 428 个小麦=低弹性抗压）+ A2 收敛信息
  （sheep→0 一致收敛、goose→顶格 6、carrot 假设否决）。
- 动作：日程表按 A2 收敛方向手工修订（羊砍掉、鹅加满、麦作为价格地板资产加量），
  单独 racing 验证——A2 的病态解（靠压对手）不采纳，但方向信息采纳。

### R3：执行密度（L3，场景 7 大改）
- 证据：idle 0.74 vs Majkel 0.478；分区驻守微负说明小修无效。
- 动作：任务束（一次出门带齐麦+肥沿途服务）、驻区待命（干完活留在任务密集区
  而非回仓）。抬 solo 上限（93k→110k+），R1 见效后此轮收益才会兑现到对战。

### R4：节拍对抗精细化（L2）
- 证据：Majkel 卖出相位 t%4==1 主导（0.57-0.64）；启发式线证伪的是无条件相位，
  条件版（y68r 镜像 +79）方向存活。
- 动作：错开对手卖出相位（读对手历史相位偏好——对手卡片已有此字段），
  卡片数据直接变成 knowledge 反制配置的第一个消费者。

### R5：y68 资产移植（L2/L3）
- 证据：room_guard/front_run/贫困陷阱救灾在 y68 系全部验证为正。
- 动作：按场景 4 挂点逐条移植，每条独立 racing。

### R6+（滚动）：从每轮归因长出——不预设。

## 四、与 Majkel 的差异化声明（防止「复刻即天花板」）

Majkel 不建模对手（对 7 类对手动作几乎一样），这是它留下的空间：
R1/R4 的对手条件层是它没有的能力；它的已知弱点（囤货抛售型 0.38 胜率、
重复商店数量盲区、不买第 4 块地）在 R2/R4 的表修订里逐个对症。
纯复刻上限≈Majkel；超越靠「Majkel 骨架 + 对手条件反制」。
