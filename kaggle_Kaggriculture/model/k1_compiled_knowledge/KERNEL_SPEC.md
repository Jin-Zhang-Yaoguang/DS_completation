## 内核规则（按实测翻译）

- **M1 同格清空**：单位所在格有可做任务时继续做完，不离开。
- **M2 格内次序**：动物格 FEED → COLLECT_FERTILIZER → HARVEST → CARE；
  作物格 HARVEST → WATER → FERTILIZE。
- **M3 纯就近派活**：非生存任务不分优先级桶，全局按（距离, 次序）贪心匹配；
  目标按「格」占用（一格一人），避免多人奔同一格。
- **M4 生存任务先行**：濒死喂养/濒枯浇水仍先于就近匹配（保零饿死红线）。
- **M5 小批高频领麦**：途经仓库且持麦 < 2 时领 3 个；不做大批补给。
- **M6 肥料不进仓**：施肥只由随身携带者执行，肥料来自收肥动作；不从仓库领肥。

## 种植吞吐诊断：隐形旧乘数（2026-09-15）

逐日测量（新内核 + 新池，seed 1046 vs y68g，final 94.8k）：

- 日种植限速（7）**不是**瓶颈：每天实种 0-7 块，大多 2-5；仅 d9-11 触顶。
- d11-25 空地 21-33 块、种子 9-16 个、现金 4k→7 万，但**目标面积仅 35-45**，
  与在种 33-38 持平——上限是目标面积本身。
- 根因：knowledge.json tuning 残留 2026-09-13 solo 口径 CEM 的 `crop_scale`
  （草莓 ×0.613、小麦 ×0.5）及 `animal_scale` ×1.22、`fert_scale` ×1.266，
  叠乘在方案池日程表之上。池里「草莓峰值 33」实际执行约 20、「小麦 28」约 14。
  两轮新内核迭代搜索均在这层隐形折扣下进行。
- 教训：**框架里的旧 tuning 会静默污染新搜索空间的语义**——新维度接管某个量后，
  旧的同类乘数必须清零或纳入同一搜索空间。

### 对手收入按品类拆解（4 seed，带旧乘数 → 去全部旧乘数）

- 金币：K1 55.0k → 62.9k（+7.9k）；y68g 128.1k → 151.0k（+22.9k）。
- y68g 涨在：**草莓 +10.3k（卖出量不变 139→139，单价 109→183）**、牛奶 +6.2k（120→134）。
- K1：草莓 +12.0k（126→150）、小麦 +1.6k；胡萝卜 -4.6k（54→6）、羊毛 -2.6k、瓜 -2.0k。
- 解读：同量卖出高价 = 对手出货时刻市场草莓更紧缺，由双方种植/卖出节奏交错决定；
  样本少且 t0 随机抽方案，机制不下定论。可行动结论：**K1 决策显著改变对手收入**，
  只看自身收入的 fitness 在盲飞。
- 行动：清除旧乘数（面积完全交给搜索维度）；tune_iter fitness 改为
  `margin + 0.5×own + 0.15×solo`，对手 y68g + y68c 两家。
