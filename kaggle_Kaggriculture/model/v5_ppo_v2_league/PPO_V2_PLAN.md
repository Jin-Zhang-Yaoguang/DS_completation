# PPO v2（第三方审查修订版）

修订依据：独立数据科学家只读审查；本版固定 V1 主基线、V2 安全对照，并将数据泄漏、策略族群有效性、嵌套模型选择和宏步奖励定义写成执行门槛。

## 2026-08-19 执行修订（G4 失败后的暂停条件）

本计划的完整 PPO 联赛不再以“继续增加轮数”作为默认下一步。`full28`
等权、`full28q` 困难对手加权和 temperature 1.5 pilot 均未通过困难族群门槛：
V3 得分率分别约 17.19%、16.41% 和 9.38%。同一加权 iter5 checkpoint 的
family-gate 开启/关闭 A/B 消融在 896 场配对中均为 V3 9.375%，因此 gate
不是该切片的可证实主因。关闭手工 SAFE_RESIDUAL 后，确定性部署的非默认
宏率为 0；同状态 stochastic-vs-argmax 审计虽有 6.5% 宏差异，却没有进入
部署路径。由此新增硬性前置条件：

1. 在重新训练前必须通过 action-closure audit：训练采样动作、确定性部署
   动作和最终实际市场订单三者的差异要逐宏步记录；非默认宏变化不能由手工
   residual 单独提供。
2. BC 数据必须报告有效动作序列数、各动作头熵和正/负干预样本数；若
   `duplicate_action_rows / rows > 0.95`，不得把 100% accuracy 当作泛化证据。
3. 必须先完成 A/B/C 消融：当前策略、关闭 gate、一个预注册单头干预。C
   第 10 天 head3=value0 的 896 场结果为总得分 85.379%、V3 0%，已拒绝。
4. 在上述条件满足前暂停 full28q warm-start、temperature 调参和 G5；下一
   个训练候选必须扩展到可表达开局模板/生产路线的动作，并用真实干预收益
   形成平衡标签。公开冠军 Replay 仍只作 holdout，不进入训练。

### 当前执行结果（2026-08-19）

- 已完成 512 条 low/high 路线反事实标签的 BC→3×512 PPO pilot；V1 配对
  128 场得分 52.73%（CI `[42.58%,62.89%]`）、hard-V3 资格 18.75%，拒绝。
- 已搜索 12 个不依赖 Replay 的 low/high 单次切换模板（768 场、0 错误）；
  最佳仍仅 37.50% 对 V1 的 54.69%，拒绝。
- 已筛选并扩展验证一个合法早期市场变体 `cow_delayed`（128 场、0 错误）：
  53.91% 对 V1 的 56.25%，平均金币差 −4,508，拒绝。
- 因此当前两路线动作空间和简单市场订单扰动均未形成可训练正标签；不得
  继续在这些标签上增加 PPO 轮数。下一候选需新增可审计的开局/整季模板生成
  器，并同时保存 intervention、seed、seat、opponent family 与实际订单变化，
  先通过至少 128 场 paired uplift 筛选，再开始 BC/PPO。
- 后续 hard-V3 全天 head3 反事实扫描找到了可部署的市场残差：第
  `[12,15,18,20,23,24,28]` 天将动物产品出售倍率设为 0.5。该残差包裹
  现有 PPO checkpoint 后通过了当前本地 G4 gate：V1 2,000 场 71.425%
  （CI `[69.20%,73.70%]`）、V2 2,000 场 78.10%、64 seed 六族群池无下降、
  hard-V3 128 场 +28.91pp、动作变化率 9.49%、Replay 回归中性。这里的
  “通过”只表示 screened residual challenger 的本地证据，不表示 PPO logits
  已学习该残差；线上仍需单独授权和 80 场监控。

## 1. 目标

PPO v2 的目标不是继续扩大对 V1/V2 固定轨迹的专门克制，而是训练一个面对未知排行榜策略仍能稳定提高胜率的分层策略。

最终候选目录暂定为 `model/v5_ppo_v2_league/`。V4 编号已用于 PPO 前的多层规则基线 `v4_rule_hybrid`。线上入口仍为 `agent(obs)`，提交只依赖 NumPy；训练端继续使用 JAX/Flax/Optax。

主要成功标准：

1. 以 V1 作为唯一主基线和冻结的低层安全执行器；V2 只作为安全回归对照，不作为 PPO v2 的默认教师或主比较对象。
2. PPO 决策必须在线下和 Replay 审计中产生可观测的有效动作变化，不能再次退化为默认宏动作。
3. 模型选择必须基于多样化对手池，而不是只看对 V1/V2 的直接胜率；最终 test 只能使用一次。
4. 本地最终验收通过后才构建 challenger；线上提交仍需单独授权。
5. 线上提交后必须保持活跃到至少 80 场公开 Episode，按实验总账中的第 1–40 场爬坡期和第 41–80 场稳定期分别验收。

## 2. 已知问题与设计响应

| PPO v1 / V3 现象 | PPO v2 响应 |
| --- | --- |
| V3 对 V1/V2 直接得分率约 84.6%，但线上 Rating 未超过 V1 | 使用多对手联赛和最差策略族群指标选模 |
| V2 平均金币提高，但临界失败增多 | 终局胜负作为主奖励，金币差只保留很小权重 |
| V3 最近抽查的 5 场线上 Replay 与 V2 的 719 个动作完全一致 | 新增宏动作、实际动作改变率和干预收益审计 |
| 第 3 天结构门控会把共享固定开局的未知策略误判为同族 | 改为每日更新的连续 opponent embedding，不做一次性硬分类 |
| V2 的喂养保护和种子裁剪可能破坏 V1 的同步与库存缓冲 | 固定 V1 为主基线；V2 仅作安全回归对照，把每项保护做成独立可选宏动作并先消融 |
| 早期弱对手和 Rating 路径会夸大累计胜率 | 线上固定 40 场爬坡 + 40 场稳定窗口，少于 80 场不下结论 |

## 3. 策略架构

### 3.1 固定低层执行器

- 以 `v1_adaptive_market` 为唯一保守回退执行器和主基线；V4 分层规则只作为候选教师/对手，不把 V4 的 V2 回退当作 V1 的安全证据。
- 前 72 个可行动回合完全冻结；第 72–167 步只允许在 V1/V4 已验证的整段开局模板中选择，不开放逐工人原子控制。
- 第 7 天开始允许神经策略选择生产路线、开局模板和市场残差。
- 最后 5 个可行动回合始终由 V1/V2 已验证的终局清仓逻辑接管。
- 模型、特征、权重或动作出现异常时，本局余下时间回退 V1。

### 3.2 日级 recurrent policy

- 每天 `hour=0` 计算一次策略，共约 30 个 token。
- 自身经济特征和对手公开特征分别编码，再输入 GRU。
- 初始建议结构：
  - self encoder：`Linear(128)`
  - opponent encoder：`Linear(64)`
  - fusion：`Linear(128)`
  - recurrent core：`GRU(96)`
  - policy/value trunk：`MLP(128)`
- 使用 8–16 天片段的 truncated BPTT；正确处理 episode reset、terminal、padding 和 action mask。
- 提交时导出 NumPy 权重与固定归一化参数，禁止线上依赖 JAX。

### 3.3 对手表示

每天更新 opponent embedding，输入至少包括：

- 已解锁地块、工人数、农民位置。
- 作物和动物计数、成熟度、可见产能。
- 对手公开资金及其日变化。
- 市场价格、库存及日变化。
- 对手生产结构在最近 1/3/7 天的变化。
- 已解锁商店与剩余时间。

不使用用户名、Team ID、Submission ID、Episode ID、私有库存或其他不可在线获得的信息。

### 3.4 宏动作空间

第一阶段只开放可解释且能由安全执行器实现的动作：

1. 生产路线：`low` / `high` / `mixed`。
2. 普通作物出售倍率：`0.5 / 1.0 / 1.5`。
3. 高价作物出售倍率：`0.5 / 1.0 / 1.5`。
4. 畜产品出售倍率：`0.5 / 1.0 / 1.5`。
5. 出售排序：原计划 / 实时价格优势 / 对手同类产能优先。
6. 小麦安全库存：V1 原值 / `+4` / `+8`。
7. 动物喂养保护：关闭 / 仅最后安全时刻 / 提前保护。
8. 种子裁剪：关闭 / 仅胡萝卜 / 全非小麦作物。
9. 清仓时点：原计划 / 提前 1 天 / 提前 2 天。
10. 作业优先级：原计划 / 收获优先 / 卸货出售优先。

不在第一版中让网络直接控制每个工人的移动、地块坐标或逐回合原子动作。

## 4. 对手联赛

### 4.1 活跃池与历史仓库

- 每轮目标激活 28 个有效不同的对手，允许 24–32 个的窄范围波动；有效策略族群不得少于 12 个。
- 历史仓库保留 100–300 个策略，但不在同一轮全部均匀采样。
- 每轮 2,048 场按 manifest 的整数配额执行；默认 24 个普通对手各 64 场、4 个困难对手各 128 场。

建议组成：

| 类型 | 数量 | 示例 |
| --- | ---: | --- |
| 固定锚点 | 5 | V1、V2、V3、V4、starter |
| 生产路线专家 | 6 | low/high/mixed、畜牧、高价作物、不同扩张速度 |
| 市场策略专家 | 5 | 抢购、压价、延迟出售、提前清仓、同类商品竞争 |
| 漏洞攻击者 | 4 | 小麦、喂养、仓容、种子、终局清仓 exploiter |
| 历史 PPO 快照 | 4 | 最近快照与行为差异最大的旧快照 |
| 强者 Replay 代理 | 4 | 榜一和前十公开 Replay 行为克隆出的可执行代理 |

默认配额正好为 28 个。每轮 2,048 场时，24 个普通对手各 64 场，4 个当前最难对手各 128 场，合计 `24×64+4×128=2,048`；若池缩减或扩展，必须在 manifest 中重新给出可加总的配额，不得同时声称所有对手 64 场且困难对手额外 100–160 场。

### 4.2 采样策略

- 25% 固定锚点，保证跨轮指标可比较。
- 25% 生产与市场策略族群。
- 25% 最近最容易击败当前策略的 prioritized opponents。
- 15% 历史 checkpoint，防止灾难性遗忘。
- 10% 随机参数扰动和分布外策略。

对手去重不能只看文件哈希；需要比较第 7 天后的动作、生产结构、出售时间和市场订单分布。行为高度相似的多个模型只计作一个有效策略族群。每轮 manifest 必须记录有效族群数、各族群样本数和去重规则；低于 12 个有效族群时不得进入完整 PPO。

## 5. 数据与行为克隆

### 5.1 数据来源

- V1、V2、V3 本地自动对局。
- V1/V2/V3 的公开线上 Replay。
- 榜一及前十的公开 Replay；只使用 Replay 中公开 observation/action，不使用不可下载的 agent log 或私有代码。
- 强制路线、市场参数扰动和漏洞攻击者生成的数据。

### 5.2 数据切分

- 训练/验证/测试按 `source + strategy_family + episode_id + seed` 做 group split，目标比例 80/10/10；不能只按 seed 哈希切分。
- 同一 Episode、同一 seed 的双席位、同一策略 lineage 和同一生成代码版本不得跨分区。
- 榜一/前十 Replay 至少保留 20% 的完整策略族群作为 test；不能把同一冠军路线的不同 Episode 分散到 train/test。
- 对轨迹做精确哈希和近邻去重，重复或高度相似的开局、动作分布和市场订单序列只保留在一个分区。
- 保存数据清单、来源、生成代码哈希、策略 lineage、有效族群数量、去重阈值和每个分区的样本数。

### 5.3 BC 目标

- 固定开局以 V1 和公开强策略为教师；前 72 回合不重学，第 72–167 步只学习已验证模板的选择，不直接生成原子动作。
- 日级宏动作教师由 V1、经过消融验证的安全选项和强者代理共同产生。
- 使用 2%–3% label smoothing，避免初始策略完全失去探索。
- BC 结束后要求默认宏动作能够逐回合复现 V1；任何偏差必须有明确标签来源。

## 6. PPO 目标与超参数

### 6.1 奖励

终局主奖励（按每天一个宏 token，共约 30 个 token）：

```text
胜 +1，负 -1，平 0
+ 0.02 × tanh(金币差 / 25000)
```

- 金币差权重从历史 PPO v1 的 `0.1` 降到 `0.02`，只作为临界局和探索辅助；历史 v3 的 `0.1` 结果不得当作 PPO v2 证据。
- 每个宏 token 的 shaping 必须严格为 `r_t += gamma * Phi(s_{t+1}) - Phi(s_t)`；最后一个 token 使用 `terminal_reward - Phi(s_T)`，并显式记录 `Phi(s_T)=0`。
- 若后半程衰减势函数权重，必须把它作为预注册的训练日程，并验证终局胜率不因 shaping 改变；不得用任意势差替代上述形式。
- 不单独奖励囤积现金、动物存活、库存或动作改变，避免代理目标取代胜率。

### 6.2 初始超参数

- `clip=0.2`
- `gamma=0.995`
- `GAE lambda=0.95`
- 学习率 `3e-4 → 5e-5`
- entropy `0.015 → 0.002`
- value coefficient `0.5`
- 梯度裁剪 `0.5`
- target KL `0.015`，超过后提前结束当前 epoch
- 每轮 2,048 场，4 个 epoch；奖励、GAE 和 bootstrap 均以 30 个宏 token 为时间尺度，而不是把 719 个底层调用误当成 719 个 PPO 时间步。
- recurrent minibatch 以完整 8–16 天片段组织，不打乱片段内部时间顺序

## 7. 分阶段迭代

### 阶段 A：V1/V2 规则消融

在开始 PPO 前，分别测试：

- V1 原版。
- V1 + 喂养保护。
- V1 + 单作物种子裁剪。
- V1 + 全非小麦裁剪。
- V1 + 提前清仓。
- 上述通过项的有限组合。

每项至少使用 500 个未见 seed、双席位 1,000 场，对多样化对手池报告纯胜率、配对置信区间和平均金币差。V1 是主比较，V2 只作为安全回归；只有胜率不退化且安全指标不恶化的规则才能进入宏动作空间。

### 阶段 B：行为克隆

- 目标 20,000 场教师数据。
- 先训练 5 epoch，按策略族群留出集检查 log-loss、校准、路线/动作分布、动作 mask 和默认宏动作复现；不能只报告总体 accuracy。
- NumPy/JAX logits 最大误差必须 `<1e-5`。

### 阶段 C：小规模 PPO pilot

- 5 轮 × 1,024 场，共 5,120 场；这样在 12 个有效策略族群的最低门槛下，每族可以获得至少 64 场配对样本。
- 只使用不少于 12 个有效策略族群、每族至少 64 场配对样本的代表性对手；若实际池更大，必须在 manifest 中重新计算整数配额。
- pilot 验收：
  - 零非法动作、零异常退出。
  - 实际动作改变率在目标强对手池中至少 5%。
  - 改变动作的配对局面相对 V1 的 uplift 95% 置信区间下界不低于 0。
  - 非默认宏动作不能集中在单一动作头或单一天。
- 若动作改变率接近 0，不允许直接扩大训练；先修正 mask、特征或动作空间。

### 阶段 D：完整 PPO 联赛

- 初始预算 60 轮 × 2,048 场，共 122,880 场；先运行 3 个独立训练 seed，不得只依赖单次初始化。
- 每 5 轮保存 checkpoint，进入候选历史仓库前必须通过固定锚点验证。
- 训练到 20 轮后启用 prioritized opponents 和 exploiter。
- 最多扩展到 80 轮；如果连续 4 个 checkpoint 的多对手验证下置信界没有改善，提前停止。
- 3 个 seed 的完整结果先锁定，再从中按 validation 下置信界选候选；不得根据最终 test 或线上 Rating 反向挑 seed。

### 阶段 E：模型选择与最终测试

checkpoint 选择顺序（嵌套验证）：

1. 训练过程中只看 validation：多样化留出对手池的配对得分率下置信界。
2. 最差 25% 策略族群的平均得分率。
3. 相对 V1 的直接结果。
4. 平均金币差，只作同分裁决。

选定 checkpoint 和 seed 后，冻结权重，只对一次完全未触碰的 test 集进行最终验收；test 不得用于继续训练、选择动作头、选择 seed 或修改阈值。多 checkpoint、多个 seed 和多个族群比较需要预注册或进行多重检验校正。

不得使用线上 Kaggle Rating 反向选择训练 checkpoint。

## 8. 本地验收门槛

### 8.1 功能与推理

- 特征长度、归一化、GRU reset、BPTT mask、动作 mask 单元测试通过。
- 默认宏动作在 1,000 个 seed、双席位下逐回合复现 V1。
- 模型加载失败、本局异常和 OOD 回退 V1。
- 干净解包、自博弈、双席位、719 次调用、720 回合 `DONE/DONE`、零 stderr。
- NumPy 单次日级推理 `<5ms`。

### 8.2 对手与泛化

- 对 V1：1,000 seed、双席位 2,000 场，作为主效果估计。
- 对 V2：1,000 seed、双席位 2,000 场。
- 多样化强对手池：至少 4,000 场。
- 从未参与训练的强者代理和公开 Replay 回归：至少 1,000 场或等价固定轨迹审计。
- 综合配对得分率相对 V1 提升至少 2 个百分点，95% CI 下界仍高于 `+2pp`；V2 只报告安全对照，不替代 V1 主结论。
- 任一主要策略族群相对 V1 的下降不得超过 2 个百分点，且每个主要族群的 95% CI 下界不得低于 `−2pp`（按预注册的多重检验校正）。
- 最差 25% 策略族群不得出现统计显著退化。

### 8.3 干预有效性

- 报告神经启用率、非默认宏动作率、实际动作改变率和回退率。
- 按每个动作头、日期和对手族群报告动作改变分布。
- 对同 seed、同席位、同对手进行 `V1` 与 `V1 + neural residual` 配对，报告干预条件下的胜率差、金币差和 95% uplift CI；被安全执行器 mask 掉的动作不能计作有效干预。
- 若实际动作改变率 `<5%`，候选不得提交；若改变率很高但配对 uplift CI 下界不高于 0，同样不得提交。

## 9. 线上验收

- 提交前必须获得单独授权。
- 提交后不得在其完成 80 场公开 Episode 前上传新版本将其挤出最近两个活跃名额。
- 第 1–40 场：爬坡期，报告胜/平/负、纯胜率、平均金币差和对手 Rating；仅作运营监控。
- 第 41–80 场：稳定期，使用相同指标单独报告，并作为主要线上结论。
- 少于 80 场不得宣布 PPO v2 优于历史版本；即使完成 80 场，80 场窗口仍是固定监控口径，不替代本地一次性 test。
- 若要声称线上 superiority，需至少 200–400 场同期、同席位/同 seed 设计的 V1 或 V2 对照；Rating 不能替代配对置信区间。
- 超过 80 场后记录扩展/稳态窗口，但不改写固定的前 80 场结果。
- Rating 只作辅助；若稳定期胜率下降，即使 Rating 暂时较高也不判定通过。

## 11. 停止与回滚条件

- pilot 实际动作改变率接近 0：停止，修正特征、mask 或动作头。
- 多对手验证连续 4 个 checkpoint 无改善：停止完整训练。
- 任一主要对手族群下降超过 2 个百分点：不构建 challenger。
- Replay 出现非法动作、动物/仓库/清仓回归恶化：回滚对应宏动作。
- 本地提升只集中在 V1/V2，而强者代理不提升：判定为对手过拟合，不提交。
- 线上前 40 场只用于爬坡诊断；最终是否通过必须等待第 41–80 场稳定期完成。

## 12. 推荐执行顺序

1. 建立 V1 规则消融矩阵。
2. 下载并压缩公开强者 Replay，训练 3–5 个可执行代理。
3. 建立目标 28 个、允许 24–32 个的初始活跃对手，并验证至少 12 个有效策略族群。
4. 实现 V1 安全执行器、连续 opponent embedding 和宏动作审计。
5. 生成 BC 数据并训练初始策略。
6. 完成 5 × 256 pilot；根据动作审计修正设计。
7. 运行 3 个随机 seed 的完整 PPO 联赛。
8. 用多对手验证选择候选，再做独立最终测试。
9. 通过全部本地门槛后构建 submission，但不自动上传。
10. 经授权上传后保持活跃至至少 80 场，按统一线上口径完成验收。
