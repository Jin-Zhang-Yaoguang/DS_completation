# V23 内核联合重写设计（定稿 2026-09-05 晚）

## 设计依据（一天 10 个假设证伪换来的负知识）

对 169k 平台的全部单点冲击均失败，因为 CornHub 的 +26k 不在任何一个机制里：
- 它少走 577 步（任务天然在身边）——但强制少走变差（放弃远处高值）
- 它多歇 297 步（PASS 686）——劳力不满载却产出更多
- 它死亡少一半——但主动救火亏（救廉价麦丢千金劳力）
- 它空地不闲置——但抬种植价值/波次/保底全变差（挤占高值任务）
矛盾的唯一解：这些属性是**同一个联合设计的副产品**，不是 10 个独立优化。

## V23 架构：计划在先、执行在后（真调度器）

当前 V22 = "每步全场估值选目标"（反应式）。V23 = 三层前馈：

### 1. 静态蓝图（赛季开局固化，象限解锁时激活）
- 牧场区：access 邻环 17-18 块（现状保留）
- 复用带 33 块：紧贴牧场，时序 甜瓜(d0-10) → 草莓(d5-27) → 快作物(d27+)
- 小麦带 20-25 块：外圈成排
- 每块的"作物生涯"在蓝图里写死，种什么不再由"谁走到了哪"决定

### 2. 每日待办队列（日初生成，按区分桶）
- 浇水桶：今日必须浇的块（窗口内小麦 + 全部 ongoing + unwatered>=1）
- 收获桶：今日到期（yu 达阈值 / 完账日）
- 种植桶：蓝图规定今日应种的块（含种子采购联动——待办数即采购数）
- 施肥桶：产出日前的草莓（肥效 3 天无缝表）
- 动物桶：喂/照料/收肥（日固定 17×3 次）
- 待办总量即当日劳力需求 → 富余即 PASS（合法歇息，不再找低值活）

### 3. 班表执行（CornHub 日程结构）
- h0-1：取货就位（饲料/种子/肥按待办量领取，一次领足）
- h2-8：动物流程 + 收获桶
- h9-17：浇水/种植/施肥桶（主力时段）
- h18-23：扫尾 + 入库（PLACE 定量）+ 卖出
- 工人从**本区**待办取最近项；区内清空才跨区支援（消灭全场折返）

### 4. 市场层
- 入库即卖 + 分相模板（洪峰全量抢先手 / 日常批 3-10 滴灌 / 终局 d28 清仓表）
- 饲料不囤：待办联动每日采购（解开"预留占仓"死结——仓库只留当日流转）
- V17 护栏 + 扰动继承

## 验收与实施

- 实现量：~450 行（复用 V22 的观测解析/移动原语/护栏），连续实现半天 + 调试半天
- 验收阶梯：G0 ≥180k（91%）才有资格进对战门；家族门加权 ≥70% 才上线
- 风险：一次性重写的调试深坑——对策：蓝图/待办/班表三层各自带独立单测（离线断言产出桶数）
