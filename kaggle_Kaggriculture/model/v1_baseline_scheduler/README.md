# v1_baseline_scheduler — 社区调研驱动的原创规则基线

> 本方案**不复刻任何一份公开 replay 动作带**：整局行为由当前 observation 现算。
> 设计依据来自 [`competition_description/public_solutions_survey.md`](../../competition_description/public_solutions_survey.md)
> 的社区共识事实，但代码为本项目自写。目的是给后续版本一条**可读、可调、可归因**的起跑线，
> 而不是直接冲榜。

## 为什么单独建这个版本

`model/v1_adaptive_market`（及其下游 v2/v3/v119）来自 Tetsutani 公开 notebook 的 replay 路线，
强度高但主体是开环动作带，难以做因果归因，也不便做参数搜索。本方案补上另一条腿：
一个每一步都能解释、每个常量都能扫的确定性调度器。两条线并存，不互相覆盖。

## 架构

```
静态地块角色规划（一次）
   ANIMAL 10 → WHEAT 4 → MELON 18 → (STRAWBERRY 0)
   按"到 shed 四个接入格的最短距离"从近到远分配：每天都要服务的畜栏压在仓库边上
        ↓
每回合：盘点农场 → 生成带优先级的任务表 → 贪心分配给农民 + 临时工
   单位在任务完成前不换目标（抑制"每回合重算导致来回走"）
        ↓
市场层：SELL 全部排在 BUY 之前（引擎按 list index 逐单位结算）
```

### 任务优先级（`main.py` 的 `tasks` 段）

| 优先级 | 任务 | 理由 |
| ---: | --- | --- |
| 0 | 给 `consecutive_unfed>=1` 的动物 FEED | 再漏一天动物永久逃走 |
| 1 | 给 `consecutive_unwatered>=1` 的作物 WATER | 今晚就会变杂草 |
| 2 | 常规 FEED | |
| 3 | 常规 WATER | 种植当天也必须浇（新苗 `consecutive_unwatered` 初始为 1） |
| 4 | PLACE 手上的动物 | 未放置的动物是死资本 |
| 5 | HARVEST 接近 `max_held` 的动物 | 满仓后的产出直接丢失 |
| 6 | CARE | 喂+照料当天累积 `pending_care_bonus`，在下一个产出日把日产从 1 提到 2 |
| 7 | BUILD_PASTURE / PLANT | 本位作物来不及成熟时自动退回种小麦 |
| 8 | COLLECT_FERTILIZER | 每头存活动物每天免费产 1 个且不累积；每动作收益仅次于甜瓜 |
| 9–11 | 收作物 / 收零散产出 / 清计划地块上的杂草 | |

### 市场层规则

- **肥料即收即卖**（社区实测其价格全程只跌：5 场 replay 终局价 20/9/1/18/4）。
- premium（MELON/MILK/WOOL/…）按价格地板 + 小批量卖，避免单笔大单在成交过程中砸穿自己的阈值。
- 小麦保留 `n_animals × 2` 天的饲料，多余按 ≥27 卖出；不足时按 `BUY_PRODUCT` 补，价格上限 70。
- 雇工只在每天第 0 回合下单（`HIRE` 占订单槽，每回合上限 10 单）。
- 买动物有三重闸门：还有空畜栏、`day <= 20`（否则来不及回本）、现金高于储备。
- `turn >= 690` 进入终局：全员回仓卸货，`SELL` 清空仓库（最后一个会被执行的 step 是 **718**）。

### 已内建的引擎坑规避

- 不读 `obs["step"]`，一律 `day * turnsPerDay + hour`。
- `SELL` 只花 shed 里的货；`HARVEST` 进的是单位随身库存，所以有独立的回仓 `DROP` 逻辑。
- `FEED` 消耗执行动作那个单位**自己身上**的 WHEAT → 单位在 shed 边会先 `PICKUP WHEAT`。
- 动物买入后进 shed，需 `PICKUP` → 走过去 → 在空 `PASTURE` 上 `PLACE`。
- shed 容量 100，买入的小麦/动物也占用；买单前留 5–10 的余量。
- 顶层 `agent()` 包了 try/except，异常时退回全 `PASS` 且 `hands` 长度对齐，保证不会 `Error`。

## 已知缺口（下一版的候选方向，按预期收益排序）

1. **共享市场完全没建模。** 现在按固定价格地板卖，不看对手供给、不看城镇解锁的商店。
   这是对强对手输 78k margin 的主因。第一优先是把 `town.unlocked_shops` 读进来做产品选择，
   并加一个"对手正在卖同一产品时提前一回合"的抢跑层（社区实测该层单独值 +1.7k~+3.2k margin）。
2. **草莓被完全放弃。** 社区数据说草莓卖进城镇坑值 $100k（全场最大市场），
   但每株要 17 天每日浇水。需要先把移动占比压下来，才养得起。
3. **移动占比过高（约 2/3 的单位回合）。** 社区基准是 55%（改成"先做完脚下这块地"之后）
   和紧凑布局的地板 33%。当前贪心分配没有做整体指派（匈牙利/最小费用流），也没有多回合路径规划。
4. **不施肥。** `FERTILIZE` 让奖励窗内的浇水从 +1 变 +2，现在肥料全部直接卖掉了。
5. **没有终局清算的精细排序。** 第 690 步起一把梭，没有按价格冲击排序，也没有分批。
6. **没有对手识别 / 镜像局处理。** 公开榜上大量对手是同一份 tape 的克隆，抢跑层收益最大的就是这类对局。

## 评测建议

不要用"对 `starter` 的金币"判断改动好坏（本地 7.7 万也只是中低段）。
下一步应接入社区的固定天梯 `raykkretzschmar/kaggriculture-reference-agents`
（10 个分档参考 agent + Bradley-Terry 排名，与官方最终口径一致），
并遵循调研报告第 3.3 节的口径：**按对每个强对手的双席位胜率判断，把"输给母体"当一票否决**。
