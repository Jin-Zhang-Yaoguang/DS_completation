# v15_closed_loop — 原创闭环调度器（"可重排执行器"路线，2026-09-03）

用户批准的"唯一剩下的路"：不再回放任何 tape，每一步由观测现算动作，使计划可以按城镇 regime 重排。
本目录记录执行器的设计、逐次迭代的诊断与当前实力。**结论先行：执行器已能与 V10 在动物侧持平，
但田间侧仍落后 15–25%，整体约为 V10 银行的 45–55%（毛线店首店城镇可达 80–120%）。**

## 文件

- `main.py`：闭环调度器（当前版本 = 分区巡回执行核心 + 槽位预算市场层 + 可覆盖的宏观计划）。
- `main_v1_backup.py` / `main_v2_backup.py` / `main_v3_greedy_backup.py`：三个历史核心（逐任务贪心 / 全局最近匹配 / 角色+匹配）。
- `diag.py` / `diag2.py`：单局 vs V10（钉商店 M6 场景），前者逐日状态 + 收入近似 + 动作构成，后者只打分数。
- `prod_diag.py`：**产量归因**——双方每天实际收获的各产品单位数、喂养/照料/浇水/施肥次数、植株数。
- `params/*.json`：`V15_PARAMS` 覆盖示例（雇工表、tape 混合、小麦收获日龄等）。
- `run_arena.sh` / `arena.log` / `eval_*.json`：64 场景 × 双席位 评测。
- 精确收入归因工具在 `../v4_demand_race/harness/exact_rev.py`（官方引擎打桩，`PIN=1` 钉商店，`DAYLOG=N` 逐日）。

## 设计

1. **布局**：牧场环 = 已解锁且到棚中心曼哈顿距离 ≤ 3 的 18 块（NW 6 / NE 6 / SW 6），动物永远贴着棚；作物由近到远。
2. **角色 + 分区**（每天重算）：牧场手 = ceil(动物数/4) 名离棚最近的单位，按蛇形顺序把牧场环切成连续段；
   其余田间手把作物地块（蛇形顺序）切成连续段。本组做完才跨组帮忙。
3. **到块即做完**：一次到访把该块当天需要的所有动作串行做完——
   动物：FEED→CARE→COLLECT_FERTILIZER→HARVEST；作物：WATER→FERTILIZE→HARVEST→PLANT→WATER；杂草：DIG→PLANT→WATER。
4. **物资**：牧场手日初在接入格 PICKUP 小麦（按本组未喂数）；田间手组内有需施肥草莓时取肥（每天 ≤ 2 次）；
   入库按随身价值/距离/时间触发（`deposit_value`/`deposit_min`）。
5. **市场**（10 槽预算）：SELL（按估值前 6）→ 饲料小麦（按当天/三天需求）→ HIRE（0–2 时分批）→ 土地 → 动物（待办跨天）→ 种子（甜瓜/草莓待办、小麦按目标地块数）。
6. **宏观计划**（`DEFAULT_PLAN`，可被 `V15_PARAMS` 覆盖）对齐 V120 蒸馏路线：10 牛 8 羊时序、雇工表、
   甜瓜 12、草莓 5/6/7/8/9/11 天 4/8/4/4/4/9、土地第 6/11 天。
7. **混合模式** `tape_until_day=D`：前 D 天原样执行 V10（tape+守卫栈），第 D 天起切闭环——用于隔离"尾段执行力"。

## 迭代与诊断（关键发现）

| 版本 | 场景0 / 1 / 2 银行（V10 约 90–100k / 120–150k / 80–95k） | 主要问题与修复 |
| --- | --- | --- |
| v1 逐任务贪心 | 1k / – / – | 动物饿死（饲料未买、喂养流程 ops 被刷新）、甜瓜只在第 0 天种 |
| v1 修喂养/市场顺序 | 35k | 现金 0 → 无法雇工；小麦买卖来回（保留量与买入触发不一致） |
| v2 任务捆绑 | 22–31k | 每收 4 麦就回仓一趟；走动 200 步/天；小麦地块被草莓挤占为 0 |
| v2 + 牧场环距离预留 + 全局最近匹配 | 31k / 97k / 34k | 动物侧仍缺喂养（12 手各自领一头动物、来回取麦）|
| v2 + 10牛8羊计划 | 45k / 122k / 26k | 动物产量对齐 V10；田间浇水只有 V10 的 60% |
| v3 角色+匹配 | 40k / 106k / 31k | 田间手空闲与跨区乱走并存 |
| **v4 分区巡回**（当前） | 47–51k / 80–83k / 37–39k | 浇水 1100+（超 V10）、小麦 350–470、动物侧 90%；草莓 100 vs 260（种得晚、施肥少） |

产量归因（场景0，全季收获单位数，V15 / V10）：肥料 339/378、牛奶 213/261、羊毛 175/196、甜瓜 66/72、
小麦 351/567、草莓 103/260；照料 335/372、喂养 346/361、浇水 972/1061、施肥 38/75。

精确收入归因（钉商店，混合 tape<20 尾段 10 天）：尾段亏损 = 小麦 −124 单位（−5k）+ 草莓 −79 单位（−1.6k）+ 肥料 −38，
其余产品持平；即**尾段差距全在田间产量**，动物侧已持平。

引擎机制层面的收获（对任何执行器都适用）：
- 动物 `pending_care_bonus` 每天喂+照料累积 1，在下一个产出日一次性兑现（上限 held=6）：羊第 6 天首产可达 6 单位，
  **每日 CARE 的价值与 FEED 相当**。
- 非持续作物只在窗口日浇水才加产（小麦第 2–4 天，胡萝卜第 2–3 天），到期未收次日开始腐烂并变杂草。
- 草莓/番茄 4 次产出后寿命终止；施肥（3 天有效）使每次产出 +1，是草莓收益翻倍的关键。
- 甜瓜第 10 天即达最大产量 6，不必等到第 12 天；先手卖出决定甜瓜均价（154 vs 241）。
- 早期现金 = 肥料（每头动物每天 1 个、约 90–100）+ 羊毛首产；晚一天买牛羊的复利损失贯穿全季。

   杂草崩盘免疫（V10 系在 4/64 场景因杂草级联损失 30–46k）。
