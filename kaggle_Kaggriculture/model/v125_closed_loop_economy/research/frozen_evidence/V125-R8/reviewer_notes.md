独立 AST 比对发现旧函数只有 `economic_plan` 改动，没有新增函数。`make_tasks`、`market_orders`、`allocate`、日历/价格/饲料/劳动模型、合同与动作/采购确认、diagnostics 均与 ea57 完全一致。模块级变化只有说明文字、候选 ID 和新参数 `investment_selection`。

`selection_score` 的行为读取只有两个位置：`main.py:543` 的专家最高分与 `main.py:555` 的许可报价排序。它还进入日志，但不直接进入合同价值或动作排序。`main.py:545` 仍以 `q.score` 更新 `st.crop_scores`；`make_tasks` 的种植任务价值保持原源码。因此未将较大的绝对净额误灌入执行价值。

预算后的净额、现金需求和劳动可行性检查没有改变；`selection_score` 在它们计算之后生成，通过原有拒绝条件的报价才进入专家评分。

## 2. 三个日志字段的语义

| 字段 | terminal_net 模式 | labor_ratio 消融 | 可解释的意义 |
|---|---|---|---|
| `net_cash_model` | 相同 | 相同 | 预测产品金额−固定投入−饲料经济成本−边际雇工；包含自有麦机会价值，不等于实际现金净流入 |
| `score` | `net_cash_model/max(1,labor)` | 相同 | 保留父版本的每动作分数，供种植执行任务价值使用 |
| `selection_score` | `net_cash_model` | `net_cash_model/max(1,labor)` | 仅用于选择专家组与项目许可顺序 |

对应 `main.py:514`–`:519`。新收据保存三项字段及 `selection_objective`，足以避免混用执行与选择分数。`selected_expert_score` / `expert_selection_scores` 属于本帧初始可行报价集合；不是专家组合总收益，也不是已经实现收益。

## 4. 消融与结论边界

1. `labor_ratio` 的动作等价要求相同观测、相同有效持久状态、相同其余参数和明确设置该参数。候选ID与新增诊断字段不同，所以不能要求完整JSON日志字节相同；不设置该参数时R8默认使用 terminal_net。
2. terminal_net 自然会改变许可集合，后续供给、现金、任务和执行轨迹也会随之变化。所保持的是执行评分公式和函数代码，不是宣称两个自然轨迹所有任务价值始终相同。
3. 排序使用本帧初始可行报价。顺序准入时会按更新后的账本重算当前项目，但不会在每次准入后对所有剩余项目重排；不能称为每一步都选“当时全局最高净值”，更不能称为组合最优。
4. 执行优先级仍可能使较高终局净额项目晚落地；选择分改变不自动证明第一笔自产销售更早。开发协议已把小额肥料首售仅视作时点指标，并配完整收益与其他守门指标，这个口径应保留。
5. 未改变的 R7 全期现金预留、未来价格与照护假设、日级劳动模型、仓容缺口和终局保守一帧都继续存在。本次隔离审查不将它们包装成已解决问题。

父的短官方动作等价检查完成后，应将其结果与最终候选哈希追加关联；现阶段无源码阻塞，不要求扩展新机制。
