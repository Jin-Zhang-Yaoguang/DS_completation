# R4 执行层原型：可确认的短期合约

## 唯一主假设

在固定 R3 的经营目标、价格预测、采购和容量选择后，将“整条 ops 必须一次满足”改成“保留真实前置条件、期限内的可行前缀、观测确认后推进”，可以减少执行层导致的可避免缺水/断粮和无效奔走，同时保留有材料、有时间时的施肥增产。这里检验执行表示，不预设总金币一定增加。

父源码为 `V125-R3`，SHA256 `d8b964487d2d635a680d0a33d83db054a593619eb29bed76bf3fcb80000df71d`。本原型是 V125 同谱系的新执行器，复用自己的 R3 副本中经营、市场、容量任务提议等函数；不调用父 agent，不依赖父文件运行，不宣称独立新策略家族。

## 合同状态定义（实现前冻结）

| 字段 | 含义 |
|---|---|
| owner / target | 工人编号、目标格；同一目标格同帧最多一个合约拥有者 |
| stages | 短序列，每步有 op、真实材料 requirement、绝对 deadline、是否必要 |
| fingerprint | 目标的种类、作物/动物和种植/放置日，阻止新对象继承旧承诺 |
| phase | ready、travelling、resupplying、awaiting_receipt；终态为 completed、cancelled、expired |
| receipt | 上一帧实际发出的动作、发出时位置/库存/目标状态、请求 step；发出后绝不前移 stages |
| expires | 从路径长度和必要前缀长度推导的最晚确认时点，不引入待调的持有期参数 |

每次调用先核对上一帧收据。位置推进、库存增加/消耗、地块状态变化等达到预期后，才确认移动或动作；MOVE/PICKUP 不算目标完成。必要操作 WATER/FEED 跨日时用存活对象的未浇/未喂计数归零确认；其他无法消歧的跨日收据记为未确认并过期，不假称完成。目标消失、身份变化、路径无进展、材料路径失效或期限不可达时取消。每日雇工重置会使旧 owner 合同失效。

已接受且持续推进的短合约保留目标，不随每帧边际排名来回跳；新出现的最后可行保活窗口允许抢占非紧迫合约。所有合约完成记录来自收据，分派次数单独计量。

## 操作依赖与可行前缀

- 作物 WATER 不需要 FERTILIZER；成熟 HARVEST 不需要施肥。只有实际执行 FERTILIZE 才需要肥料。
- 工人已有肥料，且能在必要 WATER 截止前完成 `FERTILIZE → WATER` 时保留这段增产合约。若材料不可达或时间只够 WATER，直接保活。未成熟、未肥化等条件仍来自 R3 提议。
- 动物 FEED 必须实际可取得 WHEAT；CARE 是可选收益，不能阻塞 FEED 或已存在产品的 HARVEST/COLLECT_FERTILIZER。无粮但已有产品时允许先收产品；这不视为喂养完成。
- BUILD 的准备 DIG 必须留得出 BUILD 时间；新 PLANT 必须留得出后续 WATER 时间。不能仅因 DIG/PLANT 当前能发出，就把没有后续可行路径的投资前缀当作成功。
- 原始 `make_tasks` 保持原样，仍供市场层计算雇工、种子需求等；执行器内部编译为合约，避免“拆成多个原子任务”意外放大市场层看到的任务数量。
- 日内 WATER/FEED/CARE/FERTILIZE/COLLECT 的硬截止来自实际日终，HARVEST 另受已知植物寿命约束；建设、播种仍沿用投资提议截止，所有终局操作沿用原运回约束。不能把原来为整条作物链设置的 21 点同时误当作采收截止。最后一帧整包 DROP 不在此次范围内。

仓口取料由合约明确要求的资源驱动；在途合约对仓内所需材料作当帧优先预留，避免多名工人承诺同一份供给。原终局单品返仓规则保留，普通产品搬运仍按 R3 阈值执行；不新增采购规则或补仓目标。

## 有界验证与淘汰条件

只用已存在肥料位置/晚间保活微场景、补充的人工喂养/收据拒绝场景，以及已保存 R0/R3 诊断状态的短分叉。不运行新种子完整比赛，不搜索多组参数。必须验证：远端肥料不再挡水；有肥且有时间仍施肥增产；有粮末帧可喂；无粮可以收已有产物；请求被拒不确认完成；连续移动合约不漂移；父经营/市场/容量函数源码不变；原型不导入或调用父 agent。

任何机制检查失败先保留失败证据、定位实现错误；不得用完整对局调参掩盖。通过仅表示原型可交父代理冻结、复核和分配新 seed，不表示强度或金牌门通过。
