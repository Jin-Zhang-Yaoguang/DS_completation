仍存在的解析边界

市场槽位修复已经覆盖 PASS、空列表、未知操作、缺少数量的无效订单及前 10 个槽位的截断边界。原结构可存 16 槽，当前官方配置只处理前 10 槽；保留 16 槽不会让第 11 个订单在当前配置下执行。

但 `conv_order` 仍以 C++ `cast<long>()` 再转 `int32_t` 读取数量，官方 `_parse_order` 使用 Python `int()`；这不是对所有官方可接受输入等价的转换。用未改动的 v3 和官方纯一步引擎做了 18 个双席微场景，发现 8 例差异：

| BUY_SEED WHEAT 的 quantity | 官方实际买入 | v3 实际买入 | 两席结果 |
|---|---:|---:|---|
| 整数 2 | 2 | 2 | 一致 |
| 0、-1、缺少数量 | 0 | 0 | 一致 |
| 布尔 True | 1 | 1 | 一致 |
| 浮点 2.7 | 2 | 0 | 差异 |
| 字符串 "2" | 2 | 0 | 差异 |
| 整数 2147483649 | 300 | 0 | 差异 |
| 整数 9223372036854775808 | 300 | 0 | 差异 |

每例起始现金 3000、麦种价 10，巨大正数量在官方解释器中买到现金耗尽，因此实际成交 300，而非请求的巨大数量。浮点和字符串在 C++ 转换失败后变为无效订单；超过 int32 或 long 范围的整数也不能保持 Python 的原语义。这些输入均通过 v3 当前 `basic_action_check`，不能宣称 runner 已自动限定数量域。详见 `remaining_market_boundary_probe.json`，其中每条保留实际双方状态差异。

这 19 条真实轨迹共 28567 个市场订单，其中 23430 个带数量订单；**数量全部为 Python 正整数，最大 42，没有浮点、字符串、布尔或溢出事件，也没有市场占位**。因此额外微场景差异不改变本次 19 条已存动作序列一致的结论；微场景也没有混入 19 局统计。

按本轮决定，不继续扩大引擎修复，不改变 v3 SHA。后续新策略的数量契约为 Python 正整数且不超过 100；如果其他对手产生非典型数量，保留原动作并让 parity 失败封闭，不能偷偷归一化或继续宣称等价。本文仅证明所列轨迹及已测输入的一致性，不是所有输入或线上规则的全面等价证明。
