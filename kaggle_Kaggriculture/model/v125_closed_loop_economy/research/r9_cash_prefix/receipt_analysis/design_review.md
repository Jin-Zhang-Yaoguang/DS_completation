# R9 资金收据审计：可证明范围与兑现口径

2026-09-05。独立设计审查，针对冻结 R9 `e7f1fd549fc67ccec74015299af5366812abe43ec78c4142bb019429b6bb22e0` 已知收据结构。不读取正在运行的新比赛、不导入候选/引擎、不运行场景；不改冻结源、测试或既有文档。下文是检查器设计，不是已完成的 719 帧检查结果。

## 只用收据能核对什么

每帧同时审 `initial_funding_book` 和最终 `funding_book`，使用本帧 `actual_cash=C`，当前日由 `step//24` 得到。正式接入数据时先证明 step 0–718 完整、唯一、顺序正确且文件 SHA 属于同一次已完成的运行；不要将部分输出或另一版本结果补成完整场次。

对每本账，逐日核对下式，不把存量负数截为 0：

```
E[d] = feed_cash_by_day[d] + hire_cash_by_day[d]
E[current_day] += fixed_cash_today
R[d] = 同 credit_day 的 credit_batches.cash_model 合计
B = actual_cash
for d = current_day..29:
    before[d] = B - E[d]
    after[d] = before[d] + (R[d] if d > current_day else 0)
    B = after[d]
minimum = min(before[d])
additional_current_spend = max(0, minimum)
```

应逐值对上 `expenses_by_day`、`credits_by_day`、`before_credit`、`after_credit`、`minimum`、`full_horizon_cash_outflow=sum(E)` 和 `additional_current_spend`。按源的 `-1e-9` 边界重算 `first_negative_day/feasible`；浮点加法残差与该业务判定容差分别记录，不能放大容差把实质赤字抹掉。所有数字须有限，日期只能落在当前日至 29。

批次必须按 `(credit_day, product)` 唯一、数量和金额非负、无 WHEAT/FERTILIZER；`credit_day > current_day` 且 `<=29`。这可证明账中没有当日信用和 day30 信用，不单独证明产出日期预测正确。金额为预测销售现金，不能标为银行可支用额度或实际成交。

粮食物量可用 `actual_wheat`、`existing.feed`、原缓冲定义及准入品种作有限交叉核对；本收据保存了逐日购买和期末持粮，但**没有完整共享逐日 requirements 的独立字段**。可倒算 `required[d]=stock[d-1]+buys[d]-stock[d]` 并验证非负，却不能把倒算值又代回原式称独立验证了所有喂养义务。完整义务来源需当帧真实资产/合同及日历依据。10% 余量只能核为现金，不允许乘入粮食数量。

初始/最终两本账不得简单相减后把差额称为“本帧新支出”：新许可会重价整组未来购粮与旧信用，存量费用也可能变化。`original_full_horizon_new_cash` 是父净值路径的边际现金模型，不必等于资金账总支出增量。

## 收据自身不能证明的内容

| 结论 | 现有收据能做的检查 | 缺少的独立依据 |
|---|---|---|
| 信用来自当前己方在田资产 | 检查来源坐标、批次商品与日期是否合法 | 当帧真实观察；坐标不是资产身份，来源列表还可能包含没有合格商品的己方植物 |
| 已排除新许可/在途/旧仓库商品 | 静态源资格规则；批次表不出现新增来源字段 | 同帧资产出生信息、合同/采购与实际放置事件，不能仅凭批次金额判定来源 |
| postbatch 价格与上限正确 | 初末同批数量不应增加；每批最终金额不得高于初始金额 | 收据未存每次试报价完整库存/价格模型；无法独立重算所有拒绝 trial 和其回滚 |
| 所有许可共享资金可行 | 最终全组账本前缀；正常状态和零成本复用状态分开 | 每个中间 trial 完整账未逐个落收据，不能对每项中间前缀作完全独立重演 |
| 零成本复用没有加深存量赤字 | 检查标签及原新增现金为 0；初末总账可辅助检查 | 混有其他正常许可时，初末对比不能代替该项相对准入前 baseline 的每个前缀 |
| 当前订单可由真实现金支付 | 有原始现金与最终市场意图；可做粗金额/槽数检查 | 官方执行次序、真实逐笔价格、成交量、采购拒绝/部分成交与单位动作先发生的影响 |
| 预测可行等于真实保活/交付 | 无法由财务代数推出 | 官方 FEED/WATER/HARVEST/PLACE、每日资产与逃逸/枯死/溢出事件 |

因此，账本代数全部通过只能称“收据内部资金恒等式一致”。不能顺带宣称真实付款全部成功、资金门无漏项、预测全部兑现或正式 G1 已通过。

## 预测兑现要固定一次预测时点

禁止把 719 行的 `credits_by_day` 全部相加。相邻帧经常反复预测同一只动物、同一棵作物、同一未来批产量；直接累加既重复计量，也混合不同条件下的价格预测。

建议先固定一种观察口径：每个自然日取首个真实决策时点作为一版预测，分别保存该版未来逐日批次，版本之间不相加。报告可逐版本列“预计信用日期/商品/数量/现金”和随后实际事件；同一实际成交若出现在多个预测版本的误差评估中，应标明是重复预测评估，不能再次计入全局真实销售总额。

要严格评估来自该版资产的兑现，资产身份至少需要 `(seat, position, crop或animal, planted_day或placed_day)`，并跟踪实际采收→携带→入仓→出售。后续同格新播种/新放动物不得冒充原资产。初始仓库/背包产品、本版之后新增资产以及 WHEAT/FERTILIZER 的成交不能作为本版合格信用兑现；原资产在预测时已挂在田上的可收产品则可能属于原批次。仓库同品混合时，没有完整来源流就不能精确分配某笔 SELL。

官方事件和逐日资产快照齐备后，优先报告：

- 合格资产实际采收数量、损失/未部署/死亡/逃逸及已产未售数量；
- 实际 SELL 的商品、数量、真实现金与成交日；
- 相对预计信用日的提前/准时/延后/终局仍未售；
- 在来源完全闭合时，固定预测版本的数量误差、现金误差与现金前缀实际覆盖情况。

只有按商品日期汇总的 SELL 而没有资产来源时，可以做“同期总体销售与预测信用对照”，须标 `ORIGIN_ATTRIBUTION_PENDING`，不能叫逐资产兑现率。d28 采收的 d29 信用在模型中仍晚于 d29 全部费用；实际 d29 销售早于某些费用，不反向改写已锁定的模型日内顺序。

本轮审计应把三类结论分开输出：`RECEIPT_ALGEBRA`（收据恒等式）、`OFFICIAL_REALIZATION`（真实数量/现金）、`FORECAST_ATTRIBUTION`（有资格资产来源的预测兑现）。任一部分材料不足只标该部分 PENDING，不用另一部分的通过代替。
