# R5：任务紧迫性不得奖励路远的工人

R4 开放诊断显示移动增加、生产下降。待微场景验证的具体机制：截止余量按工人计算且加巨大 urgent_bonus，使一个离目标8步的工人比已站目标上的工人得分更高；把“难以及时到达”当成额外收益。

本轮只改变紧迫性的计分和抢占判定。每个待执行目标计算所有当前可派遣工人中的最大必要阶段余量（即最快可行工人的余量）；只有这个任务即使由最快可行工人执行也到达最后窗口时，才把任务标成紧迫。该目标的所有可行边共用同一紧迫标志；移动更远不会额外加分。已有人负责的目标不能再次触发抢占。

保留 R4 的任务合同、目标维持、真实材料依赖、每次一份喂料、市场及经营计划。不混入批量取料或终局 DROP。微场景须同时验证：近端可做的任务不再派远端；只有远端可做时仍及时派遣；真实最后时点近端保活仍优先；已覆盖任务不抢占。只有机制反例成立才构造候选。

冻结 R4 的所有失败结果。后续新开发块与 R4、R0 同时比较，避免只击败退化父代；全部场景和异常保留。原开放种子只作诊断，不充当确认。

实现资格补充：共享紧迫奖励只给真正包含且可执行必要阶段的边；同格只能HARVEST而不能FEED的边不算能完成紧迫喂养。旧owner若只承诺可选采收，也不能把同格紧迫FEED计成已覆盖。active抢占与匹配使用同一资格。奖励上界包括原有1.15就地系数，取 `1 + 1.15 × 全部阶段非负价值之和`，保证词典序优先而不引入新调参幅度。
