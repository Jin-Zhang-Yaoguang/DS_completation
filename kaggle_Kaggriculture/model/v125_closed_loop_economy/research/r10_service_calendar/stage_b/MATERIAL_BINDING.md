# R10 B 粮账、物理占仓与原劳动门绑定

本模块只证明完整服务在给定未来条件下有可执行日程；资金前缀仍使用冻结 R9 的原值，路线存在不代表执行器会兑现。当前日、原本劳动可行日不出新证；原未来日 `need > capacity` 才尝试固定 12 hand，且该日原雇工款必须为 376。没有降低费用、提高原 capacity 或修改三个评分字段。

## 同一份麦的资金与物理口径

令 C 为当前日，F[d] 为完整存量、承诺和 trial 日历逐资产 FEED 数量和，R[d] 为完整资金 requirements，B[d]/S[d]/K[d] 为原 funding_feed_schedule 的 purchases/ending stock/cash。初值 I 是当前实际 shed 与全部背包内 WHEAT 之和。

- buffer = R[C] − F[C]，必须是非负整数。它包含原有周转缓冲及首只动物报价额外 3 粒，不能固定猜成 3，也不能从动物数另造一次。
- 必须核 I + B[C] − R[C] = S[C]；对每个未来日，必须同时核 R[d] = F[d]、S[d−1] + B[d] − F[d] = S[d]。任意缺日、负数、偏差均 fallback。
- 请求未来日的 `start_shed.WHEAT = S[d−1] + buffer`、`reserved_shed.WHEAT = S[d] + buffer`。原 B[d] 与 K[d] 一字不改，全部采购必须实际进入证书的 h0 仓库；h0 农夫 PASS，首批手工与麦 h1 才能用于单位动作。
- buffer 在资金账中已扣掉，在物理模型中仍占仓；同量加入期初与最低终存，不提供第二份现金信用。绑定层还核检查器的末仓麦不小于 S[d]+buffer。仅靠 SELL 保留线不能代替此末存检查。
- 原资金粮账没有把自产 WHEAT 加入可喂来源。全部 FEED 在不计自产麦时已由上述恒等式覆盖；证书必须保留原采购，采收麦另有明确 PLACE 义务，不减原费用。不允许用新产量反推更少的 BUY。

这些恒等式是原条件粮账的物量一致性，不证明未来实际买卖会完全按预测发生。特别是冻结 R9 市场逐帧补料目标、库存与执行器路线可能不同；实际兑现须单独比较。

## 其他库存的保守延续

从当前实际 shed 和所有背包统计商品，不把背包当空，不把私有 seeds 算进 shed。COW/SHEEP/GOOSE 全数延续占仓；已在途中或试项目新增待购动物也由调用方以完整 commitment manifest 明示。即使以后条件日历已投放，首版仍保留这份占仓上界，不把它当另一只可生产动物。

FERTILIZER 期初量来自当前实际量与 C..d−1 条件日历给出的产量，最多保留 12；若超额部分清空，必须明确给出“此前及时交付并卖出”的条件。上限 12 不代表免费生成 12。日末保留同样数量。

其它可售商品清零也必须有明确 prior delivery/sale 条件，且没有把这些假设销售额再加到原现金前缀。缺少此条件时，全部当前存货及先前条件产物继续占仓；WHEAT 的先前自产量只增加同量物理起存/最低终存，不增加资金信用。

所有 carry 都会占用统一 shed100；h0 原 BUY 如无法完整入仓，则没有证书。条件 bridge 不是对旧日期做过路线验证。

## 完整输入、回滚与缓存

每个 baseline/trial 输入包含完整 calendars、明确 coverage asset IDs、独立保存的原 goods/work/feed 聚合、原 workload/labor、完整 requirements 与原粮账、startup fallback 日期。校验 calendars 的原三个字段聚合逐值一致；trial 不可删除或改变 baseline calendar。源 asset 枚举本身仍是调用方对实际观测/已有承诺的责任，模块不能凭空证明不存在被漏掉的资产。

新证只解除相应未来劳动拒绝。任何当前失败、原成本非 376、字段覆盖/粮账/资源矛盾、startup 不支持或独立 checker 不过，返回原失败；已有成功日期不单独提交。返回值保留原字段与哈希，失败无输入修改。

缓存由一次 economic_plan 的独立对象持有，跨调用先核同一 plan token 与实际库存上下文；key 包含完整 DayProblem 及实现身份。只有整次 trial 全通过才提交新缓存；失败时不写入任何部分结果。缓存不表示持久经营许可，也不替代下一帧真实状态。
