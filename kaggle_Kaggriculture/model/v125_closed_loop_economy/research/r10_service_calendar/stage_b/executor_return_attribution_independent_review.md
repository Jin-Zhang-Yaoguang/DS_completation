# 返仓窄归因独立复核

结论：原归因的数值与分支条件成立。两席各24个已有观察、298个单位原子事件及冻结R9源码已只读核对，输入SHA均相符；没有候选、引擎或solver调用。

两席轨迹均为day10、step240–263。市场草莓库存首帧10000，之后23帧为9999，价格对应120→128。按R9默认base120、T100、sqrt、below_target0.7计算，库存9999的报价为round(120+84/10)=128；全部24帧等于实际观察价格。R9第242/264/630行把真实当帧库存的当日报价写入forecasts，未来项目供给只改后续日，故这里的carry_value使用该报价。

每席所有单工决策中的最大持货量为4、最大估值为512；不是声称每位工人都达到512。每席正载货原子事件267个。第1583行要求carry_value>1800、距最近仓口≤3、hour<19，且第1570行先排除已分配工人。因此这两段轨迹中，普通主动返仓移动分支不可能触发。day29强制返仓分支在day10不适用。

每席仍有2个正载货仓口事件：unit2在step252的(5,4)、step253的(5,5)，均携3份草莓、估值384，实际动作均为SOUTH。不能据阈值结论宣称“全日没有仓口机会”；在仓口的PLACE分支不要求>1800，还受前置assigned排除和可用仓容约束。此复核没有把阈值认定为全部交付缺口的唯一原因。

没有降低返仓阈值，没有验证替代路线、day11兑现或整局收益。该结论只解释所保存人工轨迹中的一个明确控制分支。
