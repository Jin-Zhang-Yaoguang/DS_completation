## 证据缺口必须保留

冻结事件含成功成交的 op/item/quantity/price/step/seat，但没有 order_index。同一帧同商品同操作出现多笔时，新工具拒绝逐笔分配，标 `PENDING_DUPLICATE_SAME_ITEM_ORDER`；它不会用 FIFO 猜价格。只有事件完整性验证及唯一映射成立，零条成功事件才可表示真实成交 0。

R8 原始 trace 只表明发了什么订单，不能证明内存中的目标、可用现金预算或下一帧原确认算了什么。因此全部相关层保持 PENDING。以后正式接入需事先冻结额外捕获：每笔原始 order_index、真实原子/逐单位 commit 及费用、采购帧前后观察、实际 PLANT 耗种/动物损失、当帧目标/许可来源和预算链、下一帧原确认。目标缺失时不得以订单数量反推目标。

现有 R0/R4 额外捕获有这些部分证据，所以工具能做旧局交叉对照；不能用它们覆盖 R8 的资料缺口，更不能代替新 8 seed × 双席正式 G1 块。

## 可复用入口

工具仅依赖 Python 标准库，不调用冻结分析器：

```
python3 audit_saved_procurement.py --mode mechanism --source <已完成官方事件目录> --output <新结果文件>
python3 audit_saved_procurement.py --mode capture --source <已保存逐笔额外捕获目录> --output <新结果文件>
```

结果已有文件时会拒绝覆盖。`mechanism` 路径只接受已审的冻结分析器 SHA；更换分析器或正式追加观测字段需另行审查和冻结，不能借本次原型自动准入。
