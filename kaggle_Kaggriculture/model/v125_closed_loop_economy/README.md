# V125：可确认的经营与任务调度

状态：`RESEARCH_ACTIVE / NOT_GOLD`。启动于 2026-09-05，用户本轮明确授权开发、实验及持续迭代；Kaggle 提交仍逐次单独授权。

## 目标与范围

把 2026-09-05 审计提出的采购确认、完整任务链、商店与对手条件计划逐项变成可证伪实验。最终停止条件见 `GATE_PROTOCOL.md`，单局利润、本地旧锚点门或模型名称不能替代金牌证据。

V125 主策略独立生成经营目标、任务、市场订单和单位动作，不调用旧完整 agent，不读取教师动作路线，不用 seed、episode 或未来商店查表。规则常量按官方解释器重述。V22 的采购补丁单独放在 `research/procurement_audit/`，只用于机制归因，不计为 V125 原创策略。

初始 R0 是可执行工程基线：三个有限预算的生产专家生成目标；Router 只依据已见商店、价格、双方公开产能与剩余时间；任务执行层从当前状态生成合法动作并确认上一帧结果。后续每代只能改变一个主要机制，失败候选冻结，下一代分配新确认块。

## 目录

- `main.py`：正在构造的主策略；每次正式实验前复制到不可变 `candidates/<id>/` 并记录 SHA。
- `research/`：假设、独立机制实验和可追溯证据。
- `evaluation/`：自然规则比赛、清单冻结和验证工具。
- `runs/`：每次实验的不可混用结果。
- `GATE_PROTOCOL.md`：本轮冻结的验收定义。

旧工作树、旧研究注册表和已打开回放均保持原状态。当前开发先使用新生成模拟场景，不把来源不明的教师数据作为训练或晋级证据。
