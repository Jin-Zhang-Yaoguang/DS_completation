# V5 Tape-Tree HMoE：分层蒸馏 + 分层搜索

> 2026-09-02。目标：对 V76/V20 胜率 ≥80%。当前最好 33.6%（V4H）。

## 0. 为什么之前的路都到不了 80%

| 路线 | 天花板原因 |
| --- | --- |
| CEM 自搜（V4） | 执行器质量（移动占 2/3 回合）卡死上限，参数怎么搜都补不回一个量级 |
| 单 tape 蒸馏（方案 A） | 开环，不适应商店分布：随机 seed −4.6k 但真实场景 18% |
| v1am 双路线 + 市场微调（V4H/V4H2） | 市场层已被上游 60 版打磨到边际 +50 金币 |

共同点：**生产计划要么固定、要么自搜**。而榜首的策略是"按商店信号分叉的树"——这正是
我们从 replay 里能直接蒸馏出来的结构。

## 1. 三层结构（对应用户提出的三个粒度）

```
L0 季度层（step 0，一次）     ：选"开局家族"——决定前 72 步的固定动作
                                 搜索对象：家族先验权重（CEM）
L1 商店层（每 24/72 步，路由）：在当前前缀一致的历史续盘中，按本局已解锁商店
                                 选最匹配的一条继续走
                                 搜索对象：商店匹配度量、胜率先验权重、分叉粒度（CEM）
L2 日层（每回合，守卫+市场）  ：weed 修复 / hands 对齐 / 一回合前移 / 终局兜底
                                 搜索对象：前移条件、终局起点（CEM）
```

**核心机制：前缀一致的 tape 树（prefix-consistent tape tree）。**
把某支榜首队伍的全部公开对局按"前 24·d 步动作 hash"组织成树：同一节点下的对局
在第 d 天开始时农场状态**必然完全相同**（动作逐步一致），因此在节点处切换到任一
子续盘都是状态一致的——这解决了"多 tape 路由必须在开局前决定"的死结。
路由走到第 d 天的节点时，看本局已解锁商店，在子续盘中选商店上下文最相似的
一条（Jaccard），平局按历史胜率/样本数。叶子 = 一场具体对局的剩余 tape。

这等价于**在商店决策粒度上蒸馏榜首的条件策略**，而不是蒸馏一条轨迹。
榜首自己就是这么分叉的（kaito 分析：同开局、step 161 起 market 分叉、step 170 起
field 分叉），我们只是把它的分叉表抄下来并配上路由。

## 3. 评测与搜索

- 评测：M6 协议（64 真实场景 × 双席位、商店钉住、kagsim）。
- CEM 只搜 L0/L1/L2 的路由与守卫参数（~10 维），不搜生产动作。
- 每队一棵树，先各自跑 M6 选底盘；再考虑跨队根节点路由。

## 4. 可证伪预测

- 第一版树（tetsuya 或 Crop Dusta 树 + 守卫 + 前移）M6 ≥ 40%，否则树的前缀
  一致性或商店匹配有实现错误。
- CEM 调 L1 参数后 ≥ 50%。
- 80% 需要的额外层（对手收获预报 lead、终局 WinLedger）在此之后叠加。
