## 1. 研究结论与目标

V123 证明了 Top20 Replay 可以被压缩成可闭环执行的语义策略，但也暴露了两类主要风险：

1. Top20 原始数据覆盖 20 名教师、339 个 episode 和 407 条教师轨迹，正式合同却最终收缩到
   Whyme Labs 的单个训练 episode `104718864`；
2. 候选结构和教师路线长期围绕 V120 开发，fresh seed 隔离了随机种子，却没有隔离对手风格；V123
   对 V120 表现很强，但对 V21/V29 和 V76 的两组 64 场双席位复核均只有 `28/0/36`。

V124 不以“复制某个冠军 Replay”为目标，而是研究：

> 能否从多个教师、多个对手和多个时间段的 Replay 中，提取具有重复支持度的状态条件策略，并由
> 独立 HMoE Router 在闭环中组合成跨对手稳健策略。

V124 必须同时满足以下四个目标：

- **多教师**：不能退化为单教师路线选择；
- **多轨迹**：不能从单个 episode 生成整季动作或资源模板；
- **状态条件化**：运行时动作只能由当前及历史可见状态生成；
- **多对手稳健**：V120 只是回归门，不能继续充当唯一金牌门。

V123 仅作为失败模式、回归基线和消融对照保存，不作为 V124 的父策略，也不得直接调用其完整 agent。

## 2. 非目标与硬性禁区

V124 不做以下事情：

- 不保存或查询逐回合动作 tape；
- 不按 `episode_id`、Replay SHA、seed、submission ID 或教师名称查动作；
- 不把未来商店、未来动作、未来库存或终局结果放入运行时特征；
- 不从一条“最佳 Replay”导出 30 天完整合同；
- 不以 V120、V21 或其他已知对手的失败局为目标逐条补规则；
- 不把离线准确率、局部 QA、本地平均分差或单一对手胜率当作金牌证据；
- 不调用 V76、V120、V123 或其他完整父 agent 后再覆盖部分动作；
- 不使用 2026-08-20 前、规则版本不明或 SHA/身份无法核实的 Replay 训练可晋级候选；
- 不合并账号在线 Replay 与官方每日 Replay 来覆盖任一面板失败；
- 不在未获明确授权时提交 Kaggle。

任何一项发生，当前候选直接标记为 `INVALID_RESEARCH_ARTIFACT`，不得进入下一门。

## 3. 数据来源与证据分层

### 3.1 蒸馏训练辅助面板

Top20 CLI Replay 只用于教师行为提取和模型训练，证据角色固定为：

`TOP20_TRAINING_AUXILIARY_NOT_PROMOTION_EVIDENCE`

准入条件：

- 实际对局日期 `>=2026-08-20`；
- 引擎与线上当前规则一致，当前基准为 `1.32.7`；
- 登记 `episode_id`、Replay SHA、实际日期、教师、seat、对手和 submission/team 身份；
- Replay 必须完整，预期包含 720 个状态、719 次决策；
- 全局去重键为 `episode_id + replay_sha256`；
- 教师轨迹唯一键为 `episode_id + replay_sha256 + teacher + seat`。

### 3.2 正式晋级面板

正式晋级证据仍严格分为两类：

1. **账号已提交模型产生的线上 Replay：主裁决面板**；
2. **官方每日 Replay：独立确认面板**。

两类面板必须分别按日期执行 Train/Dev/Blind 切分，最新日期保留为 Blind。不得读取 Blind 标签、
提前统计结果或用一类面板覆盖另一类面板失败。

### 3.3 数据版本冻结

每次研究开始前必须生成不可变的 `dataset_manifest.json`，至少登记：

- 所有数据源、文件路径、SHA、日期和规则版本；
- episode、教师轨迹、教师、对手家族数量；
- 每个来源面板的行数和日期范围；
- 去重前后数量；
- Train/Dev/Outer/Blind 分配；
- 所有被拒绝 Replay 及拒绝原因；
- 清单自身 SHA。

清单冻结后新增数据只能进入下一数据版本，不得静默并入正在选模的 V124 实验。

## 4. 多轴切分协议

仅按 episode 随机切分不够。V124 必须同时控制 episode、教师、对手家族和时间四个维度。

### 4.1 切分单位

最小样本单位是完整教师轨迹：

`(episode_id, replay_sha256, teacher_id, teacher_seat, opponent_family)`

同一个 episode 的双方轨迹只要任一进入 Dev、Outer 或 Blind，整局所有轨迹必须进入同一层，禁止拆分。

### 4.2 行为家族

教师家族和对手家族不得按版本名或选手名人工判断，必须基于冻结的行为指纹聚类。行为指纹至少包括：

- 作物、牲畜、土地、雇佣和商店组合占比；
- 市场买入、卖出、提前出售、批量和时段分布；
- 现金、库存、仓容和劳动力利用轨迹；
- 单位任务类型、空间覆盖和中心区域占用；
- 前期、中期、后期和终局的资源节奏；
- 完整局胜负、尾部损失和非法/空动作率只作聚类辅助，不作为教师质量标签。

V21/V29 与 V76 在现有复核中表现为同一旧谱系压力源，V124 评测时只能计作一个已知家族，不能按
三个版本重复加权。

### 4.3 四层数据边界

| 层级 | 用途 | 是否允许调参 | 关键隔离 |
|---|---|---:|---|
| Train | 拟合 Router、专家、价值与支持度模型 | 是 | episode 分组 |
| Inner Dev | 超参数、特征、专家数量和停止轮次 | 是 | episode 与时间隔离 |
| Outer Validation | 比较方法与教师家族泛化 | 否，只能选方法版本 | 教师家族、对手家族隔离 |
| Blind | 最终一次性结论 | 否 | 后续时间、未触碰对手、未触碰 seed |

推荐使用“外层留一教师行为家族、内层按 episode GroupKFold、时间前推验证”的嵌套方案：

1. 内层所有超参数只看 Inner Dev；
2. 外层轮流留出一个教师行为家族，衡量方法是否依赖某个教师；
3. 方法确定后锁定特征、结构、损失函数、阈值和训练轮次；
4. 可用全部合格 Top20 训练辅助数据重新拟合一次最终候选；
5. 重新拟合后只能进入冻结门控，不能再次调整结构。

一旦 Outer 或 Blind 结果被用于修改策略，该面板立即降级为已知开发证据。后续版本必须使用新数据、
新 seed 或未来 Replay 建立新的未触碰面板。

## 5. 多教师行为蒸馏

### 5.1 先识别行为，再选择教师

不再先选“最强教师”。正确顺序是：

1. 对所有合格教师轨迹计算行为指纹；
2. 聚类得到种植、畜牧、市场流动性、土地扩张、稳健恢复等行为族；
3. 在每个行为族内部提取重复出现的语义选项；
4. 对教师、episode 和行为家族做等权或上限加权，避免轨迹多的教师支配训练；
5. 只有跨 episode 重复出现且闭环可恢复的行为才能成为专家合同。

建议的最低支持度：

- 共享专家：来自至少 3 名教师、8 个独立 episode；
- 单教师专有专家：至少 12 个独立 episode，并覆盖至少 4 个不同对手家族；
- 任一原型、预算或时序阈值不得由单个 episode 直接确定；
- 不满足支持度的行为只保留为研究观察，不进入正式候选。

以上数字是 V124 的预注册安全阈值。若数据不足，只能停止或等待新数据，不能临时降低阈值。

### 5.2 蒸馏目标

允许使用未来窗口动作构造监督标签，但运行时不得使用未来信息。推荐标签分为：

- 三日宏观 regime：种植、畜牧、扩张、流动性或恢复；
- 日级资源预算：现金、土地、雇佣、种子、牲畜、商品和出售预算；
- 单位语义选项：任务类型、目标资源、目标区域和完成条件；
- 风险预算：最小现金、仓容预留、最大劳动力承诺和最坏损失；
- 终局合同：清仓优先级、停止生产条件和运输容量。

禁止标签直接包含可被运行时按 day/hour 唯一还原成教师动作的完整动作序列。

### 5.3 聚合方法

每个专家合同必须由多轨迹条件分布产生：

- 连续目标使用中位数、分位数或保守下界，不使用单局值；
- 离散选项使用跨教师支持度和校准概率；
- 稀有高风险动作必须通过更高支持阈值；
- 每个叶节点记录教师数、episode 数、对手家族数和有效样本量；
- 低支持叶节点不得执行高资金、高劳动力或不可逆动作。

## 6. V124 独立 HMoE 结构

V124 必须是 `strategy_parent=null` 的独立策略，拥有自己的 Router、专家集、状态合同和主要动作生成。

### 6.1 Router

Router 只使用当前和历史可见状态，至少考虑：

- 当前 day/hour 和季节阶段；
- 双方现金、土地、劳动力、作物、牲畜与仓容；
- 当前市场价格、供给、商店和已观察变化；
- 自身正在执行的语义任务及完成情况；
- 当前状态相对训练支持域的距离与不确定性。

Router 不得使用教师名称、版本号、seed、episode ID、submission ID、未来状态或测试对手标签。

### 6.2 专家建议

至少包含以下相互独立的闭环专家：

1. `crop_flow`：种植、浇水、收获和再播种；
2. `livestock_cycle`：饲养、照料、产物和肥料循环；
3. `market_liquidity`：购买、出售、现金和市场冲击；
4. `land_labor_capacity`：土地、雇佣、仓容与运输能力；
5. `recovery`：现金链、库存链或单位任务偏离后的保守恢复；
6. `terminal_liquidation`：终局停止生产和清仓。

专家输出语义意图和资源约束，统一执行器根据当前棋盘恢复合法路径与动作。任何专家都不得包装、调用或
复制完整父策略 agent。

### 6.3 风险仲裁

最终动作必须经过独立风险仲裁：

- 合法性检查；
- 现金、库存、仓容和劳动力容量检查；
- 不可逆动作支持度检查；
- 专家冲突消解；
- 分布外状态进入 `recovery`；
- 终局阶段强制进入清仓逻辑。

风险仲裁只能否决或缩减专家请求，不能偷偷调用某个父策略作为默认动作源。

## 7. 训练与选模协议

### 7.1 允许的优化目标

训练目标按优先级排列：

1. 语义选项的跨 episode 泛化；
2. 闭环合法率和 719 次调用完整性；
3. Router 相对 BestFixed 的正向翻转；
4. 跨教师、跨对手的纯胜率和尾部风险；
5. 平均分差只作次级诊断。

不允许用训练准确率或单一 Dev 胜率直接选最终候选。

### 7.2 嵌套选择

- 专家数量、树深、阈值、损失权重、特征和停止轮次全部在 Inner Dev 内确定；
- Outer Validation 只允许在预注册的方法版本之间做一次选择；
- 同一方法不得根据某个 Outer fold 的失败逐 fold 修补；
- 方法锁定后才允许生成最终候选；
- 最终候选生成后冻结全部代码、模型、合同、依赖和评测器 SHA。

### 7.3 必须保留的基线

- `BestFixed`：始终使用闭环最强的单专家；
- 等权专家；
- 无 Router 的多教师中位合同；
- V123：单教师单轨迹对照；
- V120：已知强度回归门；
- V21/V29/V76：一个已知旧谱系压力族。

Router 只有在多个外层 fold 中稳定优于 `BestFixed`，且存在可复核的正向路由翻转时才具有研究增量。

## 8. 冻结门控

### Gate 0：数据与信息边界

必须全部通过：

- Replay 日期、规则、身份、seat 和 SHA 完整；
- 全局去重完成；
- Train/Dev/Outer/Blind 的 episode 与 SHA 交集为 0；
- 教师家族和对手家族隔离符合清单；
- 运行时特征不包含禁用字段；
- 没有 action tape、逐步查表或父 agent 调用。

### Gate 1：离线外层验证

必须全部通过：

- 每个正式专家满足最低支持度；
- 至少 3 个专家在外层验证中实际被 Router 使用；
- Router 相对 `BestFixed` 有正向翻转，且没有被单个教师或单个 episode 支配；
- 各教师行为家族均有可接受表现，不能靠总体平均掩盖某家族崩溃；
- 所有离线指标明确标记为研究信号，不得写成金牌证据。

### Gate 2：已知闭环开发门

V120 和 V21/V29/V76 家族均已被研究过程观察，只能作为已知回归/开发门，不能再充当 Blind：

- 每个家族使用预注册的 Development seed，双席位运行；
- 用于发现系统性现金链、容量链、合法性和终局问题；
- 允许根据 Development 结果创建新候选；
- 任何修改都必须产生新候选 SHA，并重新通过 Gate 0 和 Gate 1。

### Gate 3：冻结本地多对手门

候选冻结后执行：

- V120 回归门 1 个；
- 至少 3 个未用于 V124 结构、教师选择或参数调整的行为独立对手家族；
- 每个家族 `64 fresh seed × 双席位 = 128 场`；
- 总计至少 512 场；
- 同一批 seed 在所有候选和对手家族间复用，以便成对比较；
- 每个家族必须独立通过，不允许合并胜率或平均分差补偿失败。

每个家族的通过条件：

- 至少 `76/128` 胜，即纯胜率 `>=59.375%`；
- 对应 95% Wilson 下界严格高于 50%；
- seat 0、seat 1 各自纯胜率均 `>=50%`；
- 128 场全部完成 719 次 agent 调用；
- 运行错误、非法动作和候选 SHA 漂移均为 0。

V21/V29/V76 只能计作一个已知家族，不能拆成多个家族满足数量要求。

### Gate 4：未来线上 Replay 主面板

只有 Gate 3 通过且用户另行授权提交后才允许进入：

- 只使用候选冻结及提交之后新产生的账号在线 Replay；
- 按 submission ID、package SHA、seat 和实际日期登记；
- 主面板结果单独判定；
- 失败时立即停止，不能用本地结果或官方每日 Replay 覆盖。

### Gate 5：官方每日 Replay 独立确认

- 只使用候选冻结后、符合当前规则的官方每日 Replay；
- 与账号在线主面板全局去重；
- 单独报告，不与主面板池化；
- 只在主面板已通过时用于确认跨商店、跨需求和跨对手稳定性。

本地 Gate 3、线上 Gate 4、官方 Gate 5 必须全部通过，才允许讨论 V124 金牌登记。

## 9. Blind 保护与失败处理

本地对手代码由同一研究者持有时，很难形成真正不可见的 Blind。因此 V124 使用两层保护：

1. **本地未触碰门**：候选 SHA、对手家族、评测器和 seed 清单先冻结，一次性打开结果；
2. **未来线上门**：冻结后新产生的账号 Replay 和官方每日 Replay 提供时间上真正未见的证据。

候选失败不会自动终止蒸馏研究。新版失败处理规则为：

- Gate 0 或 Gate 1 失败：当前候选退役；修复方法并换候选 SHA，已经打开的 Outer 降级为开发证据；
- Gate 2A 机制门失败：先修复 Option/现金/产能闭环，不运行大规模对手门；
- Gate 2B 增量门失败：当前确认块降级为诊断集，下一候选必须使用新的确认块；
- Gate 2C 绝对门失败：若相对父候选有合格增量，可作为研究基线继续 Rn+1，但不能进入 Gate 3；
- Gate 3 失败：当前候选退役，对手与 seed 面板永久暴露；下一候选建立新 Blind，重大机制变化升版；
- Gate 4 失败：当前候选标记 `ONLINE_PRIMARY_FAILED / NOT_GOLD`，研究可在新候选和新日期数据上继续；
- Gate 5 失败：当前候选标记 `OFFICIAL_CONFIRMATION_FAILED / NOT_GOLD`，不得用主面板或本地结果覆盖；
- 任何打开过的 Development、Blind 或在线面板都只能降级，不能重新成为未见证据。

Gate 2 细分为机制门、父子增量门和已知家族绝对强度门。完整状态转换、量化阈值和 R1 研究假设见
[ITERATIVE_DISTILLATION_PROTOCOL.md](ITERATIVE_DISTILLATION_PROTOCOL.md)。

不得因为结果接近阈值、平均分差为正或某个席位很好而临时改变规则。

## 10. 候选退役与研究重设计

以下情况只退役当前候选，不结束研究计划：样本泄露、单教师退化、Router 退化、Gate 2/3/4/5 失败、
依赖旧规则数据或候选 SHA 漂移。失败证据必须保留，并进入下一轮根因分类。

连续 3 个具有独立主假设、独立 SHA 和全新确认块的候选都无法相对父候选建立增量时，计划进入
`REDESIGN_REQUIRED`。此时禁止继续微调原结构，必须改变表示、数据覆盖或执行机制；获得新证据后可
恢复，不能通过降低阈值恢复。

因此“停止”只适用于某个候选或某个已污染面板；研究主线采用
`失败归因 → 单一假设 → 新候选 → 机制门 → 配对增量门 → 绝对门` 的循环。

## 12. 预注册决策

在训练开始前，本方案固定以下决策：

1. V124 不继承 V123；
2. 不选择单一冠军教师作为整季合同来源；
3. V120 是回归门，不是唯一金牌门；
4. V21/V29/V76 只算一个已知对手家族；
5. 本地冻结门至少包含 4 个家族、每族 128 场、总计至少 512 场；
6. 每族至少 76 胜且 Wilson 下界高于 50%，两个席位分别不低于 50%；
7. 账号在线主面板与官方每日确认面板分别判定；
8. 任一正式门失败均不得通过修改阈值、池化样本或重复打开同一 Blind 补救；
9. 单个候选失败后允许创建下一代，但每代只允许一个主机制变化和一个全新确认块；
10. 增量通过只允许成为研究基线，Gate 2 绝对线不通过时不得打开 Gate 3；
11. R1 在候选清单和新确认块提交前保持 `DESIGN_READY_NOT_STARTED`。
