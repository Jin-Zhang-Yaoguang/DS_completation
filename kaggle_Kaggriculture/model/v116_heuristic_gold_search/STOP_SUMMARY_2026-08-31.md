## 3. 社区讨论带来的研究判断

调研记录见 `lineage_and_community_report.md`。可复用的结论是：

1. 多路线或多专家组合并不自动产生增益。完整路线包含隐状态、资本节奏、库存和任务债务；只按某个 step 替换后缀，常因状态不兼容而退化。
2. 启发式调度应先处理脚下可执行任务，再做全局匹配；Hungarian/MCMF 可降低局部冲突，但不能替代跨回合任务束、补给回路和截止时间证明。
3. 719 步长、稀疏奖励和巨大组合动作空间使纯 PPO 很难直接学出完整强策略。更合理的是确定性安全执行器承载底层动作，规则/浅树或低维 RL 只做高层专家、商品和阶段选择。
4. 对方路径预测必须通过关闭消融产生真实正翻转；若只改变分差或没有行为差异，应永久关闭，不能把复杂度当贡献。

因此，本轮把原创目标定义为：商店需求 Router + 至少三个真实激活的完整生产专家 + 自有状态安全执行器 + 商品级出售控制器 + 只读公开状态的浅树对手预测。候选不得包装历史完整 agent，也不得复制 Replay 动作流。

## 4. 金牌协议与 Replay 准入

金牌协议没有在失败后被放宽：

- `strategy_parent=null`；候选拥有自己的 Router、专家、状态契约和主动作生成器。
- Router 必须严格优于最佳固定专家，并产生正向胜负翻转；否则最多算强单专家，不算 Hierarchical MoE。
- 金牌池按行为去重；V29/V30 与 V21 行为重复时只计一次。
- 正式对战要求 719 calls、零 ERROR、零 schema/安全违规；平局和错误均计未胜。
- 账号线上 Replay 场景冻结面板纯胜率 `>=75%`，且官方按日 Replay 冻结面板也 `>=75%`；两面板分别报告，任一不足即失败。
- 两个座位分别 `>=75%`，每个金牌对手纯胜率不得低于 `50%`。
- 开发与冻结测试按 `episode_id / seed / 场景哈希` 隔离。

Replay 只准提取实际对局日期 `>=2026-08-20`、`module_version` 与完整 configuration 一致的数据，并按 `episode_id + replay_sha256` 去重；只保留外生商店解锁顺序/时点、配置和派生需求，禁止使用历史动作、成交、玩家位置与市场库存轨迹。

32/32 注册测试通过，MCMF 压力样例约 0.0042 秒；完整生命周期容量门却把未来维护工时重复预收，造成 PASS 3,506、PLANT 79、bank 49,166。它是“安全但不工作”的典型失败。

## 7. 为什么还不是金牌

失败不是 Router 少一个分支，也不是缺少更大的参数搜索。核心瓶颈按证据排序为：

1. **执行经济不足**：最好的独立执行器仍不能同时保持 `bank / 资产 / 移动 / 服务动作` 五个维度。
2. **跨回合闭环不完整**：生产、补种、浇水、动物补给、收割和出售存在互相抢占；局部修复常把损失转移到另一个指标。
3. **专家上限不足**：R9 固定专家全败，R13 P2 的固定专家也未过经济门；Router 没有足够强且差异化的专家可选。
4. **对手预测未产生有效增益**：R9 的市场/反碰撞浅树没有真实正翻转，按协议不能保留为“高级机制”。
5. **正式数据面板尚不可用**：strict-ready 为 0，正式双 Replay 面板没有任何胜率证据。

因此，当前最准确的研究结论是：已经形成一套原创、可审计的 Hierarchical MoE 研究框架，并系统否证了多条启发式路线；但没有形成金牌级模型。
