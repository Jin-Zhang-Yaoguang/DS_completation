# V116 启发式金牌协议（冻结）

## 2026-08-30 Replay 准入修订（最高优先级）

本节覆盖下文旧的 synthetic Development/Confirmation 口径。synthetic seed 和已暴露 R3
seed 只可用于机制诊断、执行器回归和消融，不能再产生金牌结论。

正式场景只允许来自实际对局日期 `>=2026-08-20`、且 `module_version` 与完整
`configuration` 和当前线上规则逐字段一致的 Replay。任何日期、版本或配置字段缺失、无法核验
或不一致的记录都 fail closed。按 `episode_id + replay_sha256` 去重，并以
`episode_id / seed / scenario_sha256` 为组，在 Development 与最终冻结测试之间严格隔离。

Replay 只可经过白名单提取器生成以下外生场景：

1. 商店解锁名称、顺序和时点；
2. 完整环境配置；
3. 由该商店轨迹和配置确定性派生的城镇需求。

玩家动作、成交、奖励、私有状态和市场库存/价格轨迹不得进入场景文件、模型、特征、调参或
评测输入。原始 Replay 仅保留来源核验和 SHA256 追溯。正式评测必须在双方动作仍实时影响市场
的前提下，强制使用冻结的外生商店/需求轨迹；若当前引擎不能做到这一点，结论为评测器阻塞，
不得以自然 seed 或历史结果替代。

因官方实现先按当日空地消耗 RNG 生成杂草、再抽取商店，Replay 中“实际出现的商店身份”与
历史玩家状态存在 RNG 耦合。这里遵照本协议把它定义为**固定的 Replay 条件场景**，不声称它是
自然线上反事实或因果独立变量；候选在线只能看到截至当前 step 已公开的商店，禁止读取未来
完整序列。报告必须使用“Replay 条件场景胜率”表述。

两个来源分别建账、分别裁决，禁止合并分母：

- **账号线上 Replay 面板（主面板）**：本账号提交模型产生的合格线上对局；
- **官方按日 Replay 面板（独立确认）**：官方逐日提供的合格 Replay；数量再多也不能覆盖
  主面板失败。

只有两个来源各自的最终冻结测试面板纯胜率均 `>=75%`，且同时满足下文 Router、双座位、
行为簇、单对手、719 calls、零错误和零 schema 违规门槛，才可登记金牌。任一来源不足
`75%`、为空、样本隔离失败或证据无法核验，均不得登记。

## 目标口径

主指标使用**纯胜率**：`wins / planned_games`。平局和 ERROR 都按未胜计；同时报告 Kaggle
得分率 `(wins + 0.5 * ties) / planned_games`，但不能用它替代 75% 纯胜率门。

V116 只有同时满足以下条件才可登记金牌：

1. `strategy_parent=null`，运行时不导入、调用或包装任何历史完整 agent；
2. 包内禁止 Replay 的动作流、逐步位置流、玩家状态/成交/市场轨迹或等价开环蓝图；Replay
   只可提供本协议白名单内的外生商店/配置/城镇需求场景，所有 farmer、hands 和 market 动作
   必须由当前状态差异规则生成；
3. 候选至少三个启发式专家在正式样本真实激活；Router 的纯胜率必须严格高于最佳冻结
   单专家，并有正胜负翻转；否则只能算强单专家，不能登记 Hierarchical MoE；
4. 对金牌池双座位直接对战的总体纯胜率 `>=75%`；
5. 719 次调用完整，零运行错误、零 action schema 违规；
6. 包内外逐动作、收益一致，官方 Python 1.32.7 抽样复算一致。

## 金牌池

版本主池使用 18 个行为版本：V19、V20、V21、V32、V33、V34、V37、V46、V51、
V52、V53、V54、V66、V70、V71、V72、V73、V76。V29/V30 与 V21 行为重复，
只在报告里注明，不重复加权。正式评测前另用冻结 audit seed 对完整动作轨迹做行为指纹
去重；同时报告版本等权和行为簇等权纯胜率，两者都必须达到 75%。

## 阶段

1. **源路线资格赛**：16 个已暴露、按首店分层的 official source，6 个锚点金牌，
   双座位；只用于选择可继续构造的独立底座。要求纯胜率 `>=75%`。
2. **预构造**：16 个未用于调参的 synthetic seed，6 锚点，双座位；要求纯胜率
   `>=75%`、至少三个专家激活、Router 有行为贡献、零错误。
3. **Replay 资格与隔离**：分别建立账号线上与官方按日 registry；核验日期、版本、完整配置、
   来源和哈希，白名单提取外生场景，再按 episode/seed/scenario 组隔离 Development 与冻结
   测试。原始 Replay 的非白名单字段不得进入下游产物。
4. **双来源 Development**：两个来源分开评测、分开报告；只用于版本选择与失败归因，不得与
   冻结测试混用。版本等权和行为簇等权纯胜率均须 `>=75%`，单一金牌不得低于 50%。
5. **双来源冻结测试**：候选、阈值、场景、18 个对手、评测器和引擎全部冻结后，两个来源分别
   对 18 金牌双座位评测。每个来源的版本等权和行为簇等权纯胜率都必须 `>=75%`，任何单一
   金牌不得低于 50%，两个座位分别不得低于 75%。按独立场景组 bootstrap 报告 95% CI，
   并重验 Router 对最佳固定专家的严格正贡献。

两个 Replay 来源的 Development/冻结测试在运行前必须分别冻结 registry、场景 manifest、候选
main/archive、18 个对手、评测器和模拟器 SHA256，并与 exposure ledger 做
`episode_id/seed/scenario_sha256` 三重交集检查。冻结结果禁止覆盖；ERROR 按负局计入主指标
分母。

若任一阶段失败，V116 不写入 `golden_model.md`；根据失败类型递增下一模型版本。
