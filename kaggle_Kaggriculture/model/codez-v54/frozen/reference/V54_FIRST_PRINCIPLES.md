# V54 谱系第一性原理:对手指纹 + 策略带查表(四轴架构)

> 2026-09-22 定稿。V54 谱系(v54 / v54r1 / 后续 r 系)的一切扩展都在此框架内进行,不再另起炉灶。
> 首个实例:v54r1(提交 56447333)。

## 本质

V54 谱系 = 静态带库 + 一张「(对手族指纹 × 环境条件) → 带子」查表。
所有上分改动归结为:**给这张表加行、加列、加值,或自动化表的生成**。
不触发即回落原生 V54,误判成本为零——这是整个架构的安全底座。

## 四轴

### 轴1:对手池扩容(表的行)
- 指纹 = t2 观测 `(对手现金, 市场小麦库存)`(rkey),对确定性脚本是唯一指纹。
- 已建 7 族指纹库(rkey_lib.json):V52/53、V54镜像、V41/43、V38系、qq、y68买13系、y68r2。
- 扩容优先级由**线上人口分布**决定:从 replay 统计各族出场频率,高频族先补格子。
- V54 上榜后开源 fork 人口将持续上升 → 已覆盖格子的触发率自动升值。
- 对非确定性/轻改 fork:t2 单点指纹 → 多时点投票(t2+t26+t50)/最近邻匹配,松弛识别。

### 轴2:策略带扩容(表的值)
- 现状是「选带」:克制带只能从 V54 自带 41 条里选,上限受限于带库。
- 升级为「造带」:固定对手为某族脚本,用搜索/调度器在该对局环境滚新带,存为第 42+ 条。
  (即复刻作者 tools/claude_build_*.py 生产线;kagsim 零差异引擎已具备条件。)
- 最肥靶子 = 镜像局:对手带子完全已知,存在理论"完美抢跑带"(每个商店需求先它一步)。
  v54r1 的 5/6 只是换带打破对称,离针对性抢跑还有大空间。

### 轴3:决策时点扩容(表的列)
- 现状只在 t144(首店解锁,唯一已证无损切换点)决策一次。
- 商店每 72 步解锁一家(t144/216/288/360/432/504/576),每个解锁点都是新信息到达点。
- t300 二次路由曾在 y68 底盘上证伪(无条件切换);但在「仅同族、仅确定性对手」窄条件下,
  中盘二次切换可本地精确复算,值得按窄口径重测。切换风险=带子耦合断裂,须逐局验证。

### 轴4:表生成自动化(维护流水线)
- 与作者拉开差距的关键是**生产线**而非某一版模型。
- 日更闭环:拉新 replay → 更新指纹库(检测新族/漂移)→ 对新/高频族跑同族搜索
  → 留出选表 → 独立复验(胜负优先筛选)→ 过 gate9 → 条目进表 → 打包。
- 表是纯数据,底盘不动:每次更新风险低、验证成本固定。

## 铁律(继承,不因本架构豁免)

1. 进表门槛:独立 seed 复验 + **胜负优先筛选**(净增大但胜局降=假金)+ gate9 零退步。
2. 单 seed 结论无效,须多 seed;每格子 ≥30 局独立复验。
3. 市场单顺序铁律、部署口径铁律(入口=exec 最后一个 callable)照旧。
4. 带子=高度耦合最优化产物,带内局部改动默认下坡;改动只发生在「整带切换」粒度。
5. 对真启发式对手(SpaTaro 类)本架构失效,交由风格池 v2 轨迹签名,不混入本表。

## 修正(2026-09-22 晚):换底盘必须「重选格值」,而非只复验格有效性

此前换底盘流程(V54→V56→rescue7)只做了一件事:确认已进表的格「仍优于新底盘基线」。
这漏掉了关键一步——**在新底盘上重选该格的最优带**。

实测后果(格值精炼实验,16 格 × 13 候选 × 5 seed × 3 子族,3081 局):
- 16 格中 **12 格的现值不是最优**;
- 其中 2 格现值已是**负收益**:ICE|BRUNCH 现 110 = 3/15(-1612),最优 107 = 15/15(+478);
  FM|ICE 现 110 = 3/12(-187),最优 120 = 12/12(+373);
- 另有多格从 8~13/15 提升到 15/15。

原因:格值是「带 × 我方底盘运营层 × 对手」三方耦合的产物。底盘运营层一变(V56 的止漏层、
rescue7 的终局模拟+订单簿),最优带就漂移。只验「优于基线」会让一个次优甚至负收益的带留在表里。

**新流程(换底盘标准动作,补第 4 步)**:
1. 重做底盘适配器(fr 探针 / 插入点 / 入口口径);
2. 表迁移 + 逐格复验「是否仍优于基线」;
3. **逐格重选最优带(候选短名单 × 索引 seeds × 多子族,配对口径)**;← 新增,不可省
4. 改值格用留出 seed 复验;
5. 三件套(gate9 / 动作带 / 家族 h2h)。

配套基建:combo_index(seed→组合索引)使第 3、4 步成本可控——精炼一格约 200 局,
全表 16 格约 3000 局,一次过夜即可。
