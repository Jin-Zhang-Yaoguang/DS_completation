# 冻结快速模拟器的一致性反例

本家族没有修改模拟器或 Claude 工作区。以下反例导致正式验收全面切换到官方 `kaggle_environments==1.32.7`。

- 游戏 seed：230121。
- 席位 0：冻结 Rescue7；席位 1：codez-v54-v002。
- 同一组双方动作送入两个引擎，前 481 个状态转换一致。
- 执行第 481 步动作后，到第 482 步，快速引擎的钱为 `[58219, 56097]`，官方为 `[58221, 56095]`。
- 当时其余被比较的农场、库存、市场及商店字段一致；完整订单与开市库存见 `runs/engine_mismatch.json`。
- 这证明该冻结二进制不满足本家族需要的全面逐步一致性。差异发生在市场结算，但尚未核实 C++ 内部根因，不能把它归为已确认的舍入或订单顺序错误。

基线镜像局（seed13055）通过逐步比较，只能说明那一局一致。不能据此推广到其他路线和市场订单。

处置：快速引擎仅用于候选搜索和环境索引。v002 的留出、全新 seed 确认、旧家族 gate9、现代对手随机样本全部由官方引擎实际运行双方代理，不能拿快速引擎结果填入正式验收表。

未来如修复快速引擎，应在新文件和新哈希下进行：先复现此例，再对多个 seed、席位、代理组合做逐步对照；不得覆盖此次冻结二进制或重标旧结果。
