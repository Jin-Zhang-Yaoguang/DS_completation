# 第二轮：Replay 驱动的闭环迭代

v021 已通过本地公开程序池验收并生成提交包。全新现代面板 294/320 胜，对 r14 为 63/64；旧池 360 场整局轨迹与 v002 一致；新扩展池 86/96 胜，对照 84/96。完整数字、来源归属与未知对手边界见 `../ITERATION02_REPORT.md`。v014、v019、v020 的拒绝结果保留；没有 Kaggle 上传。

## 数据如何使用

1. `online_snapshot.json`：Kaggle CLI SDK 只读快照，保留提交 ID、对手提交 ID、席位与时间。仅代表 API 返回的已完成公开对局。
2. `replay_registry.json`：50 场已准入 Replay（26 场选入的败局、24 场对照），每场 720 状态、双方 DONE、模块 1.32.7，保留原始 SHA。此样本刻意富集败局，不能计算线上总体胜率。
3. `historical_reproduction.*` 与 `source_reproduction.*`：50/50 双方历史请求复现终值；50/50 提交源码对固定对手请求逐步复现己方全部动作。提交过的 r5 必须使用 `v54r5_submitted.py`，代理目录的同名 r5 不是同一份源码。
4. `replay_ledger.*`：在官方规则中记录成功的每笔成交、雇工和买地，而非累加请求量。50 场双方初始现金 + 实际现金流水 = 最终分数，全部核平。
5. `failure_bank.json`：26 场败局的逐品种现金差来源、78 个关键窗口、原始状态与请求引用。窗口依据现金差扩大选出，只是定位线索；投资支出和售卖错峰不等同于永久损失。
6. `counterfactual_*.jsonl`：改变己方策略、固定对手历史请求的诊断实验。它不能让对手重新决策，因此不计入正式胜率。
7. `../runs/48_v021_fresh_confirmation.*`：双方都是独立运行、实时响应的程序；种子 380000–380031、双席位、5 个现代对手、3 个控制/候选，共 960 局。没有使用回放未来动作或对手真实私有库存。

## 推断与真值的边界

本轮候选的推断只读取当前合法 observation，维护已知公开对手的影子程序，从初始库存推演其可能私有状态；下一步公共现金/市场库存不吻合就淘汰该假设。被识别的对手订单供原有市场优化器使用。未知对手自动退回原控制器的预测方式。

`audit_shadow.py` 离线用真实对手库存检验推断，真实库存只进入审计断言，不会回流候选。对 r14 和 Rescue7 两场各 719 步，库存与动作均无偏差。这不是对所有未知策略可识别性的承诺。

v014 新增的生产执行层在逐工人顺序状态上，先证明原指令是无效操作，才尝试照料、收肥或采收成熟的番茄/草莓。避开移动、种植、夜间入库和末段规划窗口，并设置存量余量。`audit_idle.py` 使用官方函数独立核验 89 次改动：原指令无物理效果；新指令不消耗现金、种子和棚内存货，不改变位置，不减少携带库存。后续闭环证明这种单步检验不充分：v014/v019/v020 均出现胜局退步，v021 已停用全部额外单位动作。具体三次采收鹅蛋导致退步的对照见 `idle_regression_causal_trace.json`。

## 续跑

在项目根目录使用 `.venv/bin/python`。固定面板按任务键恢复，已有失败行不会被删除，也不会作为缺失任务重算。

```bash
.venv/bin/python kaggle_Kaggriculture/model/codez-v54/research_official.py kaggle_Kaggriculture/model/codez-v54/runs/48_v021_fresh_confirmation.json --workers 8
.venv/bin/python kaggle_Kaggriculture/model/codez-v54/research_official.py kaggle_Kaggriculture/model/codez-v54/runs/49_v021_legacy_exact.json --workers 4
.venv/bin/python kaggle_Kaggriculture/model/codez-v54/research_official.py kaggle_Kaggriculture/model/codez-v54/runs/52_v021_extended_fresh.json --workers 4
```

不要把开发用 50 场 Replay 重新命名成留出集。下一批线上泛化检验应先按对手提交 ID 和时间冻结分组，再取得或处理新回放。不要用 checkpoint 直接注入环境来恢复随机状态；应由原始 seed 和历史双边动作前缀重建，并保留库存字典插入顺序。

本轮没有 Kaggle 上传，没有改动 Claude 工作区，没有创建后台定时任务。公开上游代码、原有署名和来源均保留；本家族是派生策略研究，不宣称独立原创模型。

同一 seed 不保证不同策略消耗相同数量的随机数，也不保证后续商店序列完全一致。配对面板比较真实完整对局，按 seed 聚类；不把它解释成固定商店条件下的纯动作因果效应。
