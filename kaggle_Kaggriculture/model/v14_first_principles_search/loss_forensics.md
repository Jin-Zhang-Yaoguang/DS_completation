# V14 Loss Forensics：为什么 V13C 得分率 61.25%，纯胜率却只有 47.50%

## 结论先行

`v13c_a2_v8_no_wool_throttle`（下称 C）已经证明能从 A2 手里拿到更多 Kaggle 积分，但**没有证明能更经常赢 A2**。确认集的真实结果是 `95/55/50`：

- 纯胜率：`95 / 200 = 47.50%`；
- Kaggle 得分率：`(95 + 0.5 × 55) / 200 = 61.25%`；
- 平均金币差：`+33.735`。

因此，61.25% 的主要来源是 55 个平局贡献了 27.5 分，而不是 130 个胜局。若在同样 200 局上要求纯胜率达到 65%，必须从 95 胜增加到至少 130 胜，即**净增加 35 个胜局**。

这 55 个平局分成两种不同机制：

1. `V5 / V5` 有 20 个平局。C 在 V5 分支完全继承 A2，没有任何直接策略残差，实际上是在和同一个完整专家打镜像局。
2. `V8 / V8` 有 35 个平局。其中 32 局的首次市场差异发生在 step 417，当时 WOOL 报价已经是 `$1`；C 比 A2 多请求出售 2–4 单位 WOOL，但引擎规定 `$1` 出售不增加市场库存，因此没有后续压价。剩余 3 局首次差异发生在 step 409、WOOL 价格为 228/239，但全局请求出售 WOOL 数量与 A2 相同，去节流没有形成实际新增请求。

所有 200 局终局时，双方 shed 与 carried inventory 中的可售商品均为 0。**终局清仓不是这批 55 平局的剩余杠杆。**

最值得验证的新机制不是继续调整 WOOL 比例，而是对镜像市场的 SELL 队列做一次有界 best response。事后 oracle 覆盖审计显示：目标 27 个 `TT` source 与 6 个 `LL` source，双席位全部存在“同分支、双方当前市场队列完全相同、队列仅含至少两个 SELL、双方同回合均无 DROP/PICKUP/PLACE、至少两个商品且至少一个报价高于 `$1`”的机会，source 覆盖率为 **33/33 = 100%**。但这只是**可作用上界**：线上 `agent(obs)` 看不到对手本回合尚未提交的动作，必须先证明能由历史市场流和公开农场状态预测下一次同队列事件，不能把事后 oracle 当作可部署信号。

## 3. 55 个平局为什么没有被 C 转成胜局

### 3.1 V5 平局：C 与 A2 没有直接策略差异

20 个 V5/V5 平局来自 10 个 TT source。C 在该分支完整保留 A2，因此这是同一完整专家的镜像。8/20 局双方 719 回合动作完全相同；其余局虽有动作差异，但现金轨迹全程相等，差异来自闭环状态中的对称移动/物流反馈，不是 C 的新 residual。

这类平局需要新的 V5 专属反镜像机制，或在更早的完整专家 Router 上避免双方都进入 V5；继续修改 V8 的 WOOL 行为覆盖率为 0。

### 3.2 V8 平局：绝大多数 no-WOOL 改动发生在价格地板

V8/V8 的 35 个平局中：

- 32 局首次市场差异在 step 417，WOOL=`$1`；C 全局比 A2 多请求出售 2–4 WOOL；
- 3 局首次市场差异在 step 409，WOOL=228/239；但 C 与 A2 的全局 WOOL 请求量差为 0。

引擎的 SELL 语义是逐单位 lockstep：双方同一单位先按共同 pre-commit inventory 报价，再提交成交；价格为 `$1` 的 SELL 会获得 `$1` 现金，但**不会增加市场 supply**。因此 32 局中的额外 WOOL 请求基本是市场状态中性的，不能压低 A2 后续报价。三局高价差异又没有形成新增请求量。V8 tie 的平均现金路径也显示这一点：C 的局中最大领先仅 +44.8、最小为 −0.06，最终精确回到 0。

作为非因果关联，高价差异更常出现在胜局：V8/V8 胜局中 49/75 的首次 WOOL 差异价高于 `$1`，负局为 12/30，平局仅 3/35，而且这 3 局无实际新增 WOOL。这个分层支持“只有经济上活跃的市场错位才可能破局”，但不能从同一确认集反推一个价格阈值并宣称有效。

简单增加 WOOL 请求量也没有剂量关系：V8/V8 中 C 相对 A2 的 WOOL 请求差，胜/平/负局均值分别为 +2.80/+3.43/+2.73，平局反而最高。闭环结果的差异来自“在哪个市场状态、什么槽位、相对对手先后顺序如何”，而不是多请求几个 WOOL 这个单变量。

现金尾部也不对称：V8/V8 胜局平均终局 margin 为 +905.76，负局为 −2,048.73，平局为 0。C 在该分支赢得较多，却在失败时输得更深；这再次说明纯胜率、得分率与平均金币必须分列。

### 3.3 终局库存不是剩余解释

200/200 局中，C 与 A2 终局 shed 和 carried inventory 的 WHEAT/CARROT/TOMATO/STRAWBERRY/MELON/EGG/MILK/WOOL/FERTILIZER 都为 0。剩余对象只包括不可出售的 seeds 或个别 farm tile/animal。故：

- 提前两回合清仓不会直接回收这 55 个平局；
- 把终局“仓库为空”误当作整个季节没有库存路径风险也不正确；它只排除了 terminal unsold 这个解释。

### 3.4 C 的改动剂量太窄，且 55 个平局中有 20 个完全不覆盖

C 相对 A2 仅删除 V8 分支在第 10/17/24 天的 WOOL 0.5 节流，每局直接覆盖 1–2 个机会、约 2–5 个动作。它能提高得分率，说明局部 residual 有价值；但要从 47.5% 直接到 65%，需要 35 个净胜局，已经超出单一 WOOL 条件的现实作用面。

## 4. SELL 队列 best response 的可证伪覆盖率

### 4.1 引擎为什么允许队列博弈

每个市场槽按两名玩家“当前槽位”逐单位同时报价。若双方队列相同，例如都为 `[SELL X, SELL Y]`，双方在 X、Y 上拿到同样报价。若我方改为 `[SELL Y, SELL X]`，就会先在 Y 上改变供给，再在 X 上落后于对手。选择哪个商品先手，本质上是在“我方在哪个商品承受后手损失”与“让对手在哪个商品承受后手损失”之间做相对收益优化。

这与按当前单价做全局排序不是一回事。V11 的 `value_slot_priority / v5_price_slot` 对直接父只有 4.5% 得分率，证明“所有回合都按价值重排”会破坏完整策略的现金和市场反馈。可接受的假设必须是：只在高度可预测的镜像队列、只改变一次或极少数次、保持 SELL 商品与总量不变，并对后续闭环回归负责。

### 4.2 严格机会定义

事后审计把一个机会步定义为同时满足：

1. C 与 A2 在该 task 选择同一个完整分支；
2. 双方当前 `market` 队列逐项完全相同；
3. 队列至少 2 个槽，且每个槽都是 SELL；
4. C 与 A2 当回合 farmer/hands 都不包含 DROP、PICKUP、PLACE，避免重排后可售量与 shed 时序失配；
5. 至少两个不同商品，且至少一个商品当前报价高于 `$1`。

第 5 条是“有相对经济作用”的最低门槛，不代表某个具体 permutation 一定赚钱。

### 4.3 覆盖结果

| 模式 | source | 双席位 task | 安全且经济活跃的机会步 | SELL 槽总数 | source 任一席位覆盖 | source 双席位覆盖 |
|---|---:|---:|---:|---:|---:|---:|
| TT | 27 | 54 | 2,486 | 5,432 | 27/27 | 27/27 |
| LL | 6 | 12 | 556 | 1,262 | 6/6 | 6/6 |
| 合计 | 33 | 66 | 3,042 | 6,694 | 33/33 | 33/33 |

相反席位的机会计数在 33/33 个 source 中完全一致，所以按独立 source 去重后为 1,521 个机会步、3,347 个 SELL 槽。V5 分支贡献 988 个 task-step，V8 分支贡献 2,054 个 task-step。所有通过“双方都无 DROP/PICKUP/PLACE”的严格机会也都通过经济活跃门槛，没有仅由同商品重复槽或全 `$1` 商品造成的伪覆盖。

| 模式 | 2 槽机会步 | 3 槽机会步 | 4 槽机会步 |
|---|---:|---:|---:|
| TT | 2,090 | 332 | 64 |
| LL | 426 | 110 | 20 |
| 合计 | 2,516 | 442 | 84 |

每个机会步的商品都互不重复；6,694 个槽由 WHEAT 3,000、FERTILIZER 2,884、WOOL 462、STRAWBERRY 180、MILK 168 构成。也就是说，作用面主要是 WHEAT/FERTILIZER 的相对先后，并非另一个动物品节流变体。

平均每个机会步约 `6,694 / 3,042 = 2.20` 个 SELL 槽。如此高的覆盖说明 queue mechanism 有足够作用面，但也说明**不能每次都重排**：每局平均约 46 个可干预机会会重新走向 V11 长剂量残差的失败风险。候选必须预注册低频触发器和最大干预预算。

### 4.4 100% 覆盖不是 100% 可部署

这是最重要的限制。Kaggle 的两个 agent 同时提交动作，我方 observation 不包含对手“本回合将要提交”的 queue。上述“双方当前队列相同”是完整 Replay 的事后 oracle 条件。

因此，部署时至少要区分三种覆盖：

- **oracle coverage**：事后知道双方 queue，当前为 33/33 source；
- **predictable coverage**：只用 t−1 及更早的公开市场、农场和自己历史动作，能高置信预测对手 t 时刻 queue；尚未测量；
- **effective coverage**：预测正确、实际 permutation 产生正相对现金，并最终完成 `T/L → W`；尚未测量。

若没有第二层预测，queue best response 只是针对“对手恰好也是 A2/同路线”的盲猜，不足以安全上线到混合排行榜。

### 4.5 可部署 shadow 的最小状态

不需要保存完整 Replay，也无法精确重建对手 private state。一个 fail-open 的在线 shadow 至少要为每个 player 保存：

| 状态 | 用途 |
|---|---|
| `last_step`、player id、重置/异常标记 | 新局重置，step 回退或 schema 异常时永久退回父策略 |
| 上一回合公开 market inventory/prices、unlocked shops | 扣除确定性的 town/shop consumption，计算公开市场净流量 |
| 自己上一回合 market 请求、当时 shed、下一回合 shed | 区分自己实际可成交量与请求量，避免把自己的失败订单归因给对手 |
| 对手各商品净流量 posterior 及不确定度 | 只从 t−1 以前信息预测 t 的 queue；`$1` floor 商品必须标记不可识别 |
| V5/V8/unknown 路线 posterior、连续命中计数 | 只有行为证据持续一致时才开启 mirror 假设，不能只看单帧农场相似度 |
| 当前父策略分支、父 market queue 的 fingerprint | 在 mirror 假设下，把自己的父 queue 当作“对手 queue 相同”的预测，而非事实 |
| 本局干预次数、上次干预 step、已重排订单 ledger | 限制 1–3 次低剂量触发，避免同一销售计划反复重排 |

其中“对手 t 回合 queue”不能写入状态，因为它在我方出动作时不可见。若实现需要对手当前 action 或 private shed 才能工作，它就是 oracle，不是可提交策略。

### 4.6 parent 可比性 caveat

当前 oracle 脚本以 **V13C 为 candidate parent、A2 为 opponent**。因此它回答的是“在 C 已有 V8 no-WOOL residual 之上，再给一个能看见双方当前 action/private 的 queue oracle，组合策略的上限是多少”。即使最终纯胜率超过 65%，也不能把全部提升归因于 queue solver。

要隔离 queue residual 的因果增量，应该另做 **A2-parent queue oracle vs A2**：candidate 与 opponent 都从 A2 起步，只允许候选重排既有 SELL queue，保持完整专家、节流、worker、商品与总量不变。两种实验分别回答：

- `C + queue oracle vs A2`：组合系统的可达上限；
- `A2 + queue oracle vs A2`：queue 机制本身的直接亲子效应。

两者使用同一批已暴露 source 仍只能作机制诊断；任何性能结论都要在冻结可部署 predictor 后换全新 panel。

### 4.7 strict queue oracle 的最终天花板

在上述报告完成后，独立 oracle 任务完成了同一批已暴露 100 source × 双席位的闭环重放。它以 C 为 parent，在双方 queue 都是 SELL-only、双方无 DROP/PICKUP/PLACE 时，直接读取对手本回合真实 action 和 private shed，枚举我方现有 queue 的 permutation；只有在一步模拟中我方现金不下降且相对现金提高时才采用。

| 口径 | 原 C vs A2 | C + strict oracle vs A2 |
|---|---:|---:|
| 胜/平/负 | 95/55/50 | **151/20/29** |
| 纯胜率 | 47.50% | **75.50%** |
| Kaggle 得分率 | 61.25% | **80.50%** |

所以答案明确：**机制 oracle 的点估计达到并超过 65% 纯胜率目标。** 逐局转换为 `T→W 35`、`L→W 21`、`W→W 95`、`T→T 20`、`L→L 29`，在这批已暴露数据上没有 W→L/T 或 T→L。双席位 source 转换为：

- `TT→WW 17`、`LL→WW 6`、`LW→WW 5`、`WL→WW 4`、`WT→WW 1`；
- 保留 `TT 10`、`LW 9`、`WL 20`、`WW 28`。

收益全部集中在 V8/V8：该分支从 `75/35/30` 变为 `131/0/9`；V5/V5 的 `3/20/3` 和两个混合分支完全不变。这也修正了“有安全重排槽就一定能获利”的过度解释：V5 的 oracle opportunity coverage 虽然是 100%，但在“不降低自己一步现金”的约束下没有形成终局转换。coverage 是作用上界，不是 effective coverage。

oracle 的席位结果为 seat0 `81/10/9`、seat1 `70/10/20`，两席纯胜率分别为 81%/70%；三天纯胜率分别为 75.0%/68.18%/83.33%。它共在 171/200 局、87/100 source 触发，2,754 个 trigger step，远高于一个低风险线上 residual 应有的剂量。

该结果**不能直接变成提交结论**，原因有四个：

1. 使用的是已经暴露、已经用于 V13 诊断的 confirmatory source；
2. 读取了线上不可见的对手当前 action 与 private shed；
3. candidate parent 是 V13C 而不是 A2，收益包含 C 既有 no-WOOL residual；
4. 每局平均约 13.8 次触发，尚未证明低频可部署 predictor 能保留这些转换。

权威结果为 [`oracle/strict_summary.json`](oracle/strict_summary.json)，对应 games SHA256 为 `ccb929b9953d77f683e045a1e536668542196ef7b0f4912b67a73f1e67410317`。它证明 queue interference 的机制天花板足够高，下一阶段的核心问题已经从“有没有上限”转为“能否在不看对手当前动作/private 的条件下逼近上限”。

## 5. 五个可证伪机制

### H1：低频、对手可预测的 SELL 队列 best response

**机制。** 当历史市场流与公开农场结构高置信表明对手正在运行相同完整专家，并预测下一回合 queue 与我方相同，枚举保持 SELL 商品和数量不变的 permutation，按引擎逐单位成交规则最大化预期相对现金差；每局最多触发 1–3 次。未知或预测不一致时原样返回。

**为什么可能有效。** TT/LL oracle 作用面为 33/33 source；完整镜像 queue 当前让双方获得相同价格，理论上存在通过商品价格曲线非对称制造相对差的空间。

**必须观测。** queue 预测 precision/coverage；触发商品、槽位、报价与库存；当步双方成交现金；下一回合市场库存；最终 `W→L、T→W、L→W` 转换矩阵；按 seat、V5/V8、日期分层。

**证伪。** 在留出 source 上，预测 precision 不足、有效覆盖很低、每个新增胜局伴随同量或更多 W→L，或平均需要高频重排才有收益，即否定。`v5_price_slot` 是强制负对照，候选不得退化成通用价值排序。

### H2：用可识别商品的市场流，预测不可识别动物品的未来队列

**机制。** 从相邻公开市场库存变化扣除自己的非地板成交与可计算的 town/shop 消耗，估计对手 CARROT/TOMATO/EGG 等商品的净流量；把它们作为完整路线指纹，预测未来 1–4 回合的 MILK/WOOL/其他 SELL queue。不要直接用 WOOL=`$1` 的库存变化估计对手销量，因为地板出售不进入市场 supply。

**为什么可能有效。** 社区库存估计指出 CARROT/TOMATO/EGG 辨识度高，MILK/WOOL 会受 `$1` floor、DROP 和 overflow 污染；社区六专家实验也显示加入对手交互后结果预测从约 56.5% 提升到 67.5%。正确用途是“用可识别商品识别路线”，而不是强行精确还原每个 WOOL。

**必须观测。** 用完整公开 Replay 的真实对手动作作标签，按日期/lineage 留出；报告各商品 net-flow MAE、未来 queue 的 precision/recall、校准曲线、unknown 覆盖率，以及预测错误时的损失上界。

**证伪。** 未来同队列事件的高置信 precision 达不到预注册门槛，或预测只在与训练同源的 A2 上成立，便不能给 H1 提供可部署 gate。

### H3：第二决策点的完整专家 Router，而不是只修 V8 商品

**机制。** 开局同时 shadow V5/V8 的完整状态，在能识别对手路线后只做一次完整专家选择；若晚切状态不兼容，则把第二决策点前移到两个专家仍共享状态的最后一步。目标不是拼接 worker 动作，而是避免 V5/V5 镜像，并在对手走 V5 时选择 V8。

**为什么可能有效。** 分支错配中 V8 对 V5 为 22/12；V5/V5 有 20 个平局且 C 无直接改动。当前单次 step-72 Router 看不到之后才出现的市场指纹，存在信息时点错配。

**必须观测。** 先算 exposed panel 上的 route oracle ceiling；再用 leave-one-date/leave-one-lineage-out 预测最优完整专家，报告混淆矩阵、route coverage、状态兼容性、异常回退和 seat 分层；与“固定最佳 V8”比较，证明 Router 而非专家均值带来收益。

**证伪。** oracle ceiling 本身不足以提供 35 个净胜局、晚期可辨识信号出现时已无法安全切换，或学习 Router 不优于固定最佳专家，即否定。

### H4：V5 专属反镜像残差，但检测器必须来自真实市场流

**机制。** 只在 Router=V5、历史行为指纹连续匹配、且 queue 预测通过时执行一次 slot preemption；不用“公开农场长得像”直接判断镜像。

**为什么可能有效。** 10 个 V5 TT source 是当前 no-WOOL 的永久盲区。V9 anti-mirror 的失败证明，clone-distance 只能看到相似结构，不能证明对手当前或未来动作相同；它不否定经过校准的时序行为指纹。

**必须观测。** V5 镜像标签上的 precision、连续命中长度、首次可识别 step、触发时剩余季节；按 opponent lineage 的 false-positive；V5 TT 的 T→W 与原本 V5 W 的 W→L。

**证伪。** 对非镜像对手误触发率高，或识别时点晚于可获利 slot，直接否定。

### H5：以获胜概率而不是公开现金为状态的风险控制

**机制。** 估计终局 `P(我方现金 > 对手现金)` 的分布，而不是只看当前公开 money。特征必须包括双方公开生产结构、我方可变现库存、市场价格/库存、对手流量 posterior、剩余商店需求与 seat。高胜率状态减少方差，低胜率状态才允许一次有上行空间的 market deviation。

**为什么可能有效。** 目标是纯胜率，不是平均金币；当前大量 exact tie 和窄局表明需要控制终局分布。但 V13D 已证明“当前公开 money 领先就取消节流”是错误代理：它对 r002/A2 得分率只有 38.19%/48.61%。

**必须观测。** leave-date/lineage-out 的 Brier score、可靠性图、不同概率桶真实胜率；干预前后的终局 margin 分布和转换矩阵；尤其检查 close-W 是否被翻成 L。

**证伪。** 模型不校准、仅提高平均 margin、不提高纯胜率，或风险模式依赖当前 cash 单变量，即否定。

## 6. 对“纯胜率 ≥65%”的最低验证设计

当前 200 局 confirmatory 已经用于诊断，不能再用于宣称 V14 达到 65%。建议把门槛拆成两个阶段：

1. **机制开发集**：只用于验证 H1–H5 的中间量。必须保留原始父动作、预测 queue、实际对手 queue、当步反事实现金、触发预算和转换矩阵；不把同一 source 上反复扫参数的最高分当性能证据。
2. **全新封存确认集**：冻结唯一候选后，至少 100 个全新 source × 双席位，对 A2 共 200 局。纯胜率主门为至少 130/200；Kaggle 得分率、平均金币差只作次要指标。

必须同时报告：

- 纯胜率及按 source cluster、日期分层 bootstrap 95% CI；
- `WW/WL/LW/WT/TT/LL` source 转换；
- seat 0 / seat 1、日期、V5/V8、预测置信桶、触发商品与时点；
- 对 A2 的 `T→W、L→W、W→L`；
- 对 r002 和异质 sentinel pool 的退化，防止只学会攻击 A2；
- 719 次调用、720 states、`DONE/DONE`、零 stderr、零 fallback/loader 异常。

若目标是“证明确有优势”而非只过点估计，建议额外要求纯胜率的 source-cluster bootstrap 95% CI 下界高于 50%。若严格要求 CI 下界也达到 65%，200 局远远不够，必须扩大 source 数量。

## 7. 优先级判断

按“预期净胜局 × 可部署性 ÷ 破坏半径”排序：

1. **先做 H1 的 oracle solver + H2 的可部署 queue predictor**。oracle 覆盖已经是 100%，但预测层是成败关键。
2. **并行算 H3 route oracle ceiling**。若完整专家选择的理论上限高于队列微调，应优先 Router，而不是继续堆 residual。
3. **单独覆盖 V5 的 H4**。否则 10 个 TT source 天然不受 C 改动影响。
4. **最后才做 H5 风险控制**。它需要前述 opponent posterior；直接用公开 cash 会重演 V13D。

不建议继续投入：全局价格门槛、长期扣货、通用价值排序、只调 WOOL 比例、终局提前清仓。这些方向要么已经有强失败反例，要么在当前 55 个平局上缺少真实作用面。
