# 评测环境勘误（2026-09-02）：钉商店 arena 的 force_shops 语义错误

## 问题

`model/v4_demand_race/harness/engine.py` 的 `play()` 在钉商店模式下只在开局调用一次
`Game.force_shops(全部 8 家)`。而 `kagsim_scenario.force_shops` 的语义是"**替换当前可见的
已解锁商店前缀**"（见 `replay_arena/kagsim_scenario.cpp` L414 与 `ScenarioRunner.step_once`
每步按 `visible_from_step` 重设）。结果：**M6 的 64 个场景里 8 家商店从第 0 步就全部可见并
消耗**，城镇需求约翻倍，双方银行约翻倍（V120 镜像：失真 163k vs 修复后 70k / 非钉住 81k）。

## 影响范围

**本会话此前所有标注 "M6" 的数字都在失真环境上测得，一律作废**，包括：
V5 84.4%/87.5%、V120 74.2%、V5 vs V120 46.9%、V4H 33.6%、V4H2、方案 A 各版本、
六队树对比、最优响应制表（oracle 53%）、V7/V8 各配置、tetsuya 103951199 的 94.5%。

仍然有效的数字（非钉住 kagsim，已与官方引擎逐分对拍）：
- V5(OceanMix) vs V76 / V20：新 40 seed × 双席位 **95.0% / 95.0%**
- V120 vs V76 / V20：同一 40 seed **96.3% / 96.3%**；V120 自身金牌门 89.1%（64 随机 seed）
- V5 vs V120：40 seed **33.8%**
- tetsuya 103951199 vs V120：40 seed **32.5%**

## 修复

`engine.play()` 改为逐步揭示：开局 `force_shops(step≤0 的前缀)`，每步 `g.step()` 后
`force_shops(step≤now 的前缀)`。验证：商店在 72/144/216/…/576 逐家出现；V120 镜像银行
70k（同量级于非钉住 81k）。
